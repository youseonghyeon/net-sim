# 다음 후보 (2026-09-18 기준)

지금 팔레트(PC·노트북·서버·스위치·라우터·게이트웨이·NAT·인터넷)로 가정용·소규모 사무실 구성은 다 만들어진다.
더 넣는다면 **"새 학습 포인트가 생기는 것"** 을 기준으로 아래가 후보이고, 대부분은 하드웨어가 아니라 서비스(소프트웨어)다.
(원칙: 장치 종류를 늘리기보다 "상자 안의 소프트웨어" 를 늘린다 — DHCP 서버, DHCP 릴레이가 그렇게 들어갔다.)

## 우선순위 높음 (1·2·4 는 2026-09-18 저녁에 완료)

1. ✅ **DNS 서버** (서버 장치의 서비스 토글)
   "8.8.8.8 은 되는데 google.com 은 왜 안 되지" 를 보여준다. 호스트에 DNS 주소 설정(DHCP 가 안내), 이름 → IP 질의/응답 패킷, 캐시.
   지금 ping 이 IP 만 받는 이유가 이것이 없어서다.
2. ✅ **포트 포워딩** (라우터/NAT 박스 설정)
   "NAT 뒤의 내 웹 서버를 밖에서 접속하기". 지금은 바깥에서 시작한 통신이 전부 `NAT 테이블에 없음` 으로 버려지는데, 규칙 하나(TCP 80 → 192.168.0.20:80)로 열리는 걸 보면 NAT 의 성질이 완성된다.
3. ✅ **방화벽 규칙** (게이트웨이/라우터의 서비스) — 2026-09-19
   포트·주소별 허용/차단. "ping 은 되는데 80 은 막힘" 같은 실무 상황. 지나가는 패킷만 검사(FORWARD 체인), 첫 일치 우선, 기본 정책, 상태 추적(NEW/ESTABLISHED).

## 우선순위 중간

4. ✅ **허브** (장치)
   MAC 테이블 없이 무조건 전부 플러딩하는 옛날 장비. 구현은 스위치에서 학습만 뺀 것이라 싸고, "왜 스위치가 생겼나(충돌 도메인, 도청 가능)" 를 대비로 보여준다.
5. ✅ **무선 AP / 무선 공유기** (장치) — 2026-09-19
   케이블 없이 붙는 호스트(스마트폰). SSID 가 같고 전파 범위(300px) 안이면 자동 연결, 끌어서 멀어지면 끊김. AP 는 L2 브리지(유선 eth0 + 무선 슬롯 8), 공유기는 무선 토글. 단말끼리는 AP 가 중계, 유니캐스트는 대상 단말에게만(암호화 문구).
6. ✅ **VLAN 지원 스위치** — 2026-09-19
   포트별 액세스 VLAN + 트렁크(802.1Q 태그), VLAN 별 MAC 테이블/플러딩, 게이트웨이 서브 인터페이스(router-on-a-stick, 릴레이 포함). 예제 "VLAN 으로 나눈 사무실".

## 굳이 안 넣어도 되는 것

- 모뎀/ONT: 라우터 WAN 과 인터넷 사이의 L1 장비라 그림만 늘어난다.
- 로드밸런서, 프록시: 학습 목적(서브넷·DHCP·ARP·NAT·TCP)에서 벗어난다.

## 추천 순서

**DNS → 포트 포워딩 → 허브.** 셋 다 기존 코드(서비스 토글, NAT 테이블, 스위치)에 얹는 형태라 장치 종류를 늘리기보다 "상자 안의 소프트웨어" 를 늘리는 방향과 맞는다.

**하지 않기로 한 것 (2026-09-19 결정):** 인터넷 노드를 실제 네트워크에 연결하는 하이브리드(로컬 도우미가 실제 ping/DNS/HTTP 를 대신 실행). 시뮬레이터는 시뮬레이션에 머문다.
