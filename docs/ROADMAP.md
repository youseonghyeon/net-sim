# GL.iNet Brume 3 기능 (2026-10-06 사용자 결정: "가능한 것은 로드맵대로 쭉")

Brume 3(GL-MT5000)는 OpenWrt 기반 VPN 보안 게이트웨이다. 공식 문서(docs.gl-inet.com/router/en/4/user_guide/gl-mt5000)의 기능을 코드와 대조했다.
장치를 새로 만들지 않고 **공유기(Router)** 에 기능을 얹는다 — Brume 도 결국 OpenWrt 공유기이고, "장치보다 상자 안의 소프트웨어" 원칙.

이미 있는 것: 포트 포워딩, NAT 모드·Full Cone, IPv6(PD·RA·인바운드 기본 차단), DNS 설정, 방화벽, 클라이언트 목록(DHCP 임대 표).

하지 않는 것: QoS·SQM·2.5G·VPN 처리량(대역폭·큐 모델이 없다 — 링크는 크기와 무관하게 10ms. 넣으려면 코어 전송 모델과 기존 예제의 타이밍이 모두 바뀐다), 하드웨어 가속·펌웨어·플러그인·예약 작업·시간대·USB 하드웨어(관리 기능이라 보여 줄 패킷이 없다), 자녀 보호의 시간대 예약(벽시계가 없다).

설정 탭 구조(2026-10-07): 섹션이 늘어 공유기(네트워크·인터넷·VPN·보안)·게이트웨이(인터페이스·라우팅·보안·NAT·VPN·이중화) 설정을 묶음 칩으로 나눴다(`ui.tsx` `ConfigGroups`, 켠 기능이 있는 묶음에 점, 고른 묶음은 장치 종류별로 기억). 새 Brume 기능은 알맞은 묶음에 넣고, 앱 성격(AdGuard·DPI 등)은 "앱" 묶음을 새로 둔다.

순서 (단계마다 테스트·ui-check·push·clean-context 리뷰 → 결함 수정):
1. ✅ (2026-10-07) **WireGuard 서버·클라이언트** — 공유기 서버(피어 = 공개 키 + 터널 주소), 공유기 클라이언트(LAN 전체를 터널로, 킬 스위치, 기기별 VPN 정책, VPN DNS 로 DNS 유출 방지), 노트북·폰 클라이언트(원격 접속 VPN 종류 "WireGuard"). 키 쌍·1-RTT 핸드셰이크(Initiation/Response)·cryptokey routing(AllowedIPs)·엔드포인트 로밍·모르는 키에는 침묵·passive keepalive·응답 없으면 재핸드셰이크
2. ✅ (2026-10-07) **DDNS** — WAN 주소가 바뀌면 DDNS 서비스(인터넷 노드)에 갱신, 클라이언트는 이름으로 접속. ISP 주소 바꾸기(FORCERENEW), DNS TTL, WireGuard 이름 엔드포인트·실패 시 다시 풀기
3. ✅ (2026-10-07) **멀티 WAN 페일오버** — LAN 포트 하나를 WAN2 로(테더링·셀룰러 흉내), 추적 ping 으로 장애 감지 → 넘어감, NAT 세션이 끊기는 이유
4. ✅ (2026-10-07) **AdGuard Home·자녀 보호** — DNS 차단 목록(0.0.0.0/NXDOMAIN), 쿼리 로그·차단 통계, DNS 가로채기(53 리디렉션), 기기별 차단
5. ✅ (2026-10-07) **DPI·VPN 난독화** — SNI·DNS·모양·포트로 앱 분류, 앱별 통계·차단(RST 주입), VPN 탐지 차단을 WireGuard 난독화(AmneziaWG 식 — 모양 흐트러뜨리기·쓰레기 패킷)로 통과. TCP 443 위장은 OpenVPN(6단계)의 TCP 모드로
6. **OpenVPN** — UDP/TCP 1194, TLS 핸드셰이크·인증서
7. **Tailscale·ZeroTier** — 조정 서버, P2P 메시(기존 홀 펀칭 재사용), DERP 릴레이, 서브넷 라우터
8. **드롭인 게이트웨이·관리 접근 제어·클라이언트 차단·GoodCloud 원격 관리**
9. 후순위: SIP ALG, IGMP 스누핑, Tor, 네트워크 저장소(Samba)

# 다음 후보 (2026-09-18 기준)

지금 팔레트(PC·노트북·서버·스위치·라우터·게이트웨이·NAT·인터넷)로 가정용·소규모 사무실 구성은 다 만들어진다.
더 넣는다면 **"새 학습 포인트가 생기는 것"** 을 기준으로 아래가 후보이고, 대부분은 하드웨어가 아니라 서비스(소프트웨어)다.
(원칙: 장치 종류를 늘리기보다 "상자 안의 소프트웨어" 를 늘린다 — DHCP 서버, DHCP 릴레이가 그렇게 들어갔다.)

## 우선순위 높음 (1·2·4 는 2026-09-18 저녁에 완료)

1. ✅ **DNS 서버** (서버 장치의 서비스 토글)
   "8.8.8.8 은 되는데 google.com 은 왜 안 되지" 를 보여준다. 호스트에 DNS 주소 설정(DHCP 가 안내), 이름 → IP 질의/응답 패킷, 캐시.
   지금 ping 이 IP 만 받는 이유가 이것이 없어서다.
2. ✅ **포트 포워딩** (라우터/NAT 박스 설정)
   "NAT 뒤의 내 웹 서버를 밖에서 접속하기". 지금은 바깥에서 시작한 통신이 전부 `NAT 테이블에 없음` 으로 드롭되는데, 규칙 하나(TCP 80 → 192.168.0.20:80)로 열리는 걸 보면 NAT 의 성질이 완성된다.
3. ✅ **방화벽 규칙** (게이트웨이/라우터의 서비스) — 2026-09-19
   포트·주소별 허용/차단. "ping 은 되는데 80 은 막힘" 같은 실무 상황. 지나가는 패킷만 검사(FORWARD 체인), 첫 일치 우선, 기본 정책, Stateful 검사(NEW/ESTABLISHED).

## 우선순위 중간

4. ✅ **허브** (장치)
   MAC 테이블 없이 무조건 전부 플러딩하는 옛날 장비. 구현은 스위치에서 학습만 뺀 것이라 싸고, "왜 스위치가 생겼나(충돌 도메인, 도청 가능)" 를 대비로 보여준다.
5. ✅ **무선 AP / 무선 공유기** (장치) — 2026-09-19
   케이블 없이 붙는 호스트(스마트폰). SSID 가 같고 전파 범위(300px) 안이면 자동 연결, 끌어서 멀어지면 끊김. AP 는 L2 브리지(유선 eth0 + 무선 슬롯 8), 공유기는 무선 토글. 단말끼리는 AP 가 중계, 유니캐스트는 대상 단말에게만(암호화 문구).
   예제 정리 (2026-10-02): 묶음 순서(VPN·종합 묶음 새로), "두 집 직접 잇기" 를 메뉴에서 뺌(게이트웨이 2단·백본과 겹침), 로밍에 노트북 유선/Wi-Fi, 도커 예제를 맥 Docker Desktop 구조로 다시(게이트웨이 NAT 켜기·포트 공개 docker -p), 종합 예제 "중소기업 전체 (본사·지사·재택·고객)" 23대.
   노트북 유선·무선 NIC (2026-10-01): Wi-Fi 토글, 유선 우선 자동 전환(케이블을 빼면 Wi-Fi, NIC 마다 MAC 이 달라 주소를 새로 받음). 남은 후보: 두 NIC 동시 사용 + 인터페이스 메트릭·분할 라우팅(사용자가 B 를 먼저 고름 — 호스트를 인터페이스 여러 개 구조로 바꿔야 해서 큼).
6. ✅ **VLAN 지원 스위치** — 2026-09-19
   포트별 액세스 VLAN + 트렁크(802.1Q 태그), VLAN 별 MAC 테이블/플러딩, 게이트웨이 서브 인터페이스(router-on-a-stick, 릴레이 포함). 예제 "VLAN 으로 나눈 사무실".

## IPv6 계획 (2026-09-30 사용자 결정)

결정: **기본 꺼짐**(장치별로 켬 — 기존 구성·예제의 로그와 테스트 불변, 실제 OS 는 기본 켜짐이라는 점은 설정 칸에 안내), 인터페이스 ID 는 **EUI-64**(MAC 이 주소에 보여 SLAAC 원리가 드러남, 실제 OS 는 개인정보 때문에 랜덤이라고 로그에 안내), 4단계를 이어서(단계마다 테스트·ui-check·push·리뷰 에이전트).

배울 것: 128비트 주소·`::` 축약·/64, 링크 로컬(fe80::) 자동 주소, ARP 대신 NDP(브로드캐스트 없이 멀티캐스트 NS/NA), DAD, SLAAC(RS/RA → 프리픽스 + 인터페이스 ID), 기본 게이트웨이 = 라우터의 링크 로컬, Hop Limit·traceroute, 듀얼 스택(A/AAAA), NAT 가 없으니 방화벽이 지킨다.

구조: 이더넷 payload 에 `ipv6` 종류를 새로 추가 — 기존 코드는 `ipv4` 만 보므로 IPv6 프레임은 기본적으로 무시되어 기존 동작이 안 바뀐다. `core/addr6.ts`(파싱·RFC 5952 축약·프리픽스·EUI-64·solicited-node), `nodes/ipv6.ts`(인터페이스별 주소·이웃 캐시·NDP·DAD). L3 전달은 `forward6` 로 따로(NAT·VPN·이중화·RIP 가 얽힌 IPv4 경로를 건드리지 않음). TCP·UDP·DNS 메시지는 그대로 IPv6 안에 싣는다.

1. ✅ (2026-09-30) 기반: 주소·NDP·ping/traceroute/TCP over IPv6·게이트웨이 IPv6 라우팅(연결·스태틱·디폴트 ::/0, Hop Limit, Time Exceeded·Unreachable), 방화벽 규칙의 IPv6 주소, 스위치·허브·AP·공유기 브리지의 멀티캐스트. UI·패킷 상세·예제 "IPv6 기초".
2. ✅ (2026-09-30) SLAAC: 게이트웨이 인터페이스별 RA 광고(프리픽스·RDNSS), 호스트 "자동(SLAAC)/수동", RS/RA, EUI-64 + DAD, 기본 게이트웨이 = 라우터 링크 로컬, 거둠 RA(수명 0). 구성 검사. 예제 "IPv6 자동 주소 (SLAAC·RA)". 1단계 리뷰 결함 10건 수정.
3. ✅ (2026-09-30) 듀얼 스택: DNS AAAA(서버 레코드 A/AAAA·NODATA·IPv6 위의 DNS·RDNSS), 이름 대상은 AAAA 우선(ping·traceroute 는 폴백 없음, TCP 는 IPv6 실패 시 IPv4 — Happy Eyeballs 축소판). 예제 "듀얼 스택 사무실". (TCP over IPv6·진단 자동완성의 IPv6 묶음은 1단계에 넣었다. 인터넷 노드 IPv6 는 "ISP 가 고객 프리픽스를 어떻게 아느냐" 가 DHCPv6-PD 라 4단계로 옮김 — 가짜 경로 학습을 넣지 않으려고)
4. ✅ (2026-09-30) 공유기·인터넷 IPv6(NAT 없음): 인터넷 노드 IPv6(ISP 링크·공인 IPv6 서버·공인 DNS 2001:4860:4860::8888·공개 이름 AAAA), ISP 가 DHCPv6-PD 로 /56 위임 → 공유기가 LAN 에 /64 RA, IPv6 인바운드 기본 차단(Stateful), 인터넷 저편 클라이언트의 IPv6 접속으로 "NAT 가 아니라 방화벽이 막는다". 예제 "듀얼 스택 집".

넣지 않는 것: DHCPv6 주소 할당(stateful), NAT64/DNS64, RIPng, IPv6 위의 VPN·이중화·로드밸런서·프록시·DHCP 릴레이·VLAN 서브 인터페이스, 확장 헤더·단편화·PMTUD(MTU 모델 없음), 임시 주소(privacy extension), MLD. 주기 RA 없음(시계 구조) — 링크 업·설정 변경·RS 때만.

## 추천 순서

**DNS → 포트 포워딩 → 허브.** 셋 다 기존 코드(서비스 토글, NAT 테이블, 스위치)에 얹는 형태라 장치 종류를 늘리기보다 "상자 안의 소프트웨어" 를 늘리는 방향과 맞는다.

**하지 않기로 한 것 (2026-09-19 결정):** 인터넷 노드를 실제 네트워크에 연결하는 하이브리드(로컬 도우미가 실제 ping/DNS/HTTP 를 대신 실행). 시뮬레이터는 시뮬레이션에 머문다.
