# VPN — 사이트 간·원격 접속·L2TP·WireGuard·OpenVPN·메시(Tailscale·ZeroTier)·DPI 난독화·Tor

기능별 구현 상세 (예전 AGENTS.md "시뮬레이션 연결 방식" 에서 옮김 — 2026-10-07). 규칙·공통 메커니즘은 AGENTS.md.

- 사이트 간 VPN(`nodes/vpn.ts` `Vpn`, WireGuard 식): `L3Settings.vpn {enabled, peer, remote[]}`. 상대 대역(`remote`)으로 가는 패킷은 `route()` 가 kind "vpn"(스태틱과 같은 급) → `sendTunnel` 이 `VpnMessage{inner}` 를 UDP 51820 에 담아 상대 공인 주소로(바깥 경로는 `underlay` = VPN 경로 제외, 바깥 패킷은 내가 만든 것이라 NAT 안 함). 받는 쪽은 NAT 역변환보다 먼저 `receiveTunnel`: 안쪽 출발지가 `remote` 안이어야 풂(AllowedIPs), 받은 바깥 출발지(주소·포트)를 `endpoint` 로 기억해 거기로 답함(NAT 뒤 상대 — 엔드포인트 로밍). VPN 을 켠 장비만 터널 패킷을 풀고, 끈 장비(VPN 게이트웨이 앞의 NAT 박스)는 보통 UDP 로 NAT 역변환·포트 포워딩. 풀린 패킷은 `forward(…, tunnel=true)` 로 NAT 없이 전달, 방화벽은 터널로 나가는 것 = 아웃바운드, 풀려 들어온 것 = 인바운드. 그 패킷에 대한 ICMP 통지(Time Exceeded·Unreachable·Host Unreachable)는 LAN 인터페이스 주소로, NAT 없이(`noticeFrom`, `hostUnreachable`). 핸드셰이크·키 교환·keepalive 는 생략. **IPsec 모드**(`VpnConfig.mode: "ipsec"`, `psk`): 첫 패킷에 IKEv2 두 교환(IKE_SA_INIT: NAT 감지 = 적어 보낸 주소와 실제 헤더 비교, IKE_AUTH: PSK 비교) 후 SA up, 그동안 패킷은 큐(32). 데이터는 ESP(`EspPacket`, IPv4 payload kind "esp", 포트 없음 → NAT 가 변환 못 하고 드롭) 또는 NAT 감지 시 UDP 4500 안의 ESP(NAT-T). IKE 응답 2초 없으면 `IKE_TIMER_TAG` 로 큐 드롭 후 다음 패킷에 재협상. VPN 이 장치에 부탁하는 송신은 `VpnIo`(underlay 경로, NAT 안 함). IKE 요청은 1초마다 2번 재전송 뒤 포기(timer data 에 spi·단계·시도 횟수·요청 번호 — EAP 처럼 같은 단계의 요청이 이어져도 앞 요청의 timer 가 뒤 요청을 일찍 재전송하지 않게). SA 없이 ESP 가 오면(한쪽만 설정이 바뀌어 터널이 내려감) 받은 쪽이 새로 협상해 상대의 옛 SA 를 갈아 끼우고(`onOrphanEsp`, 실제는 INVALID_SPI 알림), 인증된 ESP 의 바깥 출발지가 바뀌면 그쪽으로 답한다(`followPeer`). NAT 감지는 양쪽이 서로 본 주소를 적어 "내 앞/상대 앞" 을 구분. 재협상(rekey) 생략. **DPD**(사용자 동작 `vpn-dpd` — VPN 섹션 "상대 확인 (DPD)". 설정 `VpnConfig.dpd`/`RaClientConfig.dpd`(기본 꺼짐)를 켜면 주기 DPD: 배경 타이머로 상대에게서 10초(`DPD_INTERVAL`) 동안 받은 것이 없을 때 보낸다 — 인증된 ESP·DPD 응답·상대의 DPD 요청을 받을 때마다 잰다(`Vpn.heard`, strongSwan dpddelay 식), 다음 차례는 마지막으로 받은 때부터 10초, DPD 설정만 바뀌면 터널을 다시 맺지 않는다, SA 가 없으면 버튼이 막히고 코어는 "연결된 터널 없음" 만 기록): `Vpn.dpd` 가 지금 SA 의 경로로(NAT-T 면 UDP 4500, 상대의 NAT 매핑 포트로) 빈 INFORMATIONAL(`IkeMessage.dpd`) → 상대는 그 SA 를 알면(SPI 가 같거나 SA 의 상대 주소에서 옴 — 양쪽이 동시에 협상하면 SPI 가 엇갈린 채 둘 다 up 이고 사이트 간 ESP 는 SPI 를 보지 않으므로) 빈 응답(`vpn.dpd` "터널 유지"), 모르면(설정 변경·재시작) INVALID_SPI → 시작한 쪽 SA 삭제. 재전송 2번 뒤 무응답이면 SA 삭제 — 둘 다 다음 패킷에 재협상. WireGuard 식은 대상 아님(버튼 숨김): 이 시뮬레이터의 NAT 매핑은 만료되지 않아 keepalive 로 지킬 것이 없고, 핸드셰이크·SA 자체가 없다. 방화벽 규칙 프로토콜에 ESP. 구성 검사 `vpn.mode-mismatch`·`vpn.psk-mismatch`·`vpn.psk-empty`·`vpn.natt-closed`(NAT 뒤 상대가 500 만 포워딩), NAT 뒤 상대는 UDP 500 포워딩을 따라간다. 서버 서비스에 SSH(TCP 22) 토글 — TCP 앱은 그대로(HTTP 흉내)이고 tcpdump·헤더에서 22 는 내용을 풀지 않는다. 패킷 상세는 바깥 UDP → VPN 층 → "터널 안 ·" 원래 패킷, tcpdump 는 `UDP, length N`(암호화라 못 풂). 구성 검사 `vpn.no-peer`·`vpn.overlap`(양쪽 대역 겹침)·`vpn.shared-peer`(두 사이트가 같은 상대 — 키가 없어 엔드포인트를 뺏음)·`vpn.peer-off`·`vpn.one-way`(상대가 VPN 을 안 켠 NAT 박스면 UDP 51820 포워딩 대상을 상대로 본다). 불러올 때 `normalizeVpn` 으로 정리.
- 원격 접속 VPN(`nodes/ravpn.ts`): 서버 `RaServer`(L3 `L3Settings.ra {enabled, psk, poolStart, poolEnd, routes, users?}`) — 클라이언트마다 SA(가상 주소 → 바깥 상대·NAT-T·SPI·사용자), IKE_AUTH 응답에 가상 주소(`assigned`)·사내 대역(`routes`, split tunnel)을 실어 준다(`IkeMessage.ra/cid/assigned/routes`, 다시 붙으면 같은 주소). **계정 인증**(EAP-MSCHAPv2 축소판, `users [{name, password}]` 가 있을 때만 — 비면 지금처럼 PSK 만): IKE_AUTH(PSK + IDi `user`) → PSK 가 맞으면 서버가 EAP 요청(`eap: "request"`, `vpn.eap`) → 클라이언트가 두 번째 IKE_AUTH 로 EAP 응답(`eapSecret`) → EAP 성공 + 가상 주소, 또는 AUTHENTICATION_FAILED(`eap: "failure"`). 클라이언트에게는 "계정 또는 비밀번호가 틀림" 만, 서버 로그는 "목록에 없음/비밀번호가 다름" 을 구분. 클라이언트에 계정이 없으면 EAP 요청을 받고 거기서 실패(재전송 없음). EAP 요청이 사라져 클라이언트가 첫 IKE_AUTH 를 다시 보내면 서버는 EAP 요청을 다시 보낸다(`eapPending`), EAP 도중 계정 목록이 비면 PSK 만으로 받아 준다. 서버는 IKE_AUTH 의 마지막 응답(EAP 성공·실패, PSK 만 쓰는 응답, INTERNAL_ADDRESS_FAILURE)을 클라이언트("바깥 주소:포트")마다 보내기 전에 기억해(`lastAuth`, RFC 7296 2.1) 그 응답이 사라져 같은 요청(SPI·EAP 여부가 같음)이 다시 오면 인증·주소 할당 없이 그대로 다시 보낸다(`vpn.ike` `resent`) — 그러지 않으면 서버에 유령 세션이 남고 노트북은 "응답 없음 … UDP 500·4500" 으로 원인을 잘못 짚는다. Delete·설정 변경·이중화에서 물러남 때 지운다. 학습 포인트: PSK 는 모두의 공통 비밀이라 한 명을 막으려면 모두의 키를 바꿔야 하지만 계정은 그 사람 것만 지우면 된다. 사용자 목록만 바뀌면 붙어 있는 세션은 유지된다(인증은 접속할 때 한 번 — 실무와 같음, 다시 붙을 때 막힘). 같은 사용자가 두 기기로 동시에 붙으면 둘 다 받아 주고 가상 주소를 따로 준다(클라이언트 식별은 MAC) — strongSwan 기본값(`uniqueids=yes`: 같은 ID 로 새로 붙으면 옛 SA 를 교체)과 다르다. 서버 표에 "사용자" 열, 요약에 `kim 10.99.0.10`. 클라이언트 DPD(`RaClient.dpd`, 동작 `vpn-dpd`): 사이트 간과 같은 빈 INFORMATIONAL, 무응답이면 SA 삭제 후 끊김(state failed, 요약 "끊김 ·", "다시 연결"), 서버가 모르면 INVALID_SPI → 다시 접속. 라우팅은 붙은 가상 주소를 kind "ra"(/32, 가장 먼저)로 그 클라이언트 터널에. 받은 ESP 는 안쪽 출발지가 붙은 가상 주소면 원격 접속, 아니면 사이트 간 VPN(`Vpn.handleIke` 는 `m.ra` 를 무시). 클라이언트 `RaClient`(호스트 `HostSettings.ra {enabled, server, psk, user?, password?}`) — 주소를 받으면(DHCP·Probe 끝) 접속, `NetInterface.outbound` 훅으로 사내 대역행 패킷의 출발지를 가상 주소로 바꿔 ESP 로 감싸고, 받은 ESP 는 목적지를 실제 주소로 되돌려 호스트에 넘긴다(호스트 코드는 실제 주소를 그대로 씀). 끄면 INFORMATIONAL(Delete, 임대 반환). 터널 자신(ESP·NAT-T·IKE)·서버 주소·직접 연결된 서브넷행은 가로채지 않는다(가로채면 바깥 패킷이 다시 감싸져 무한 재귀). 서버의 IKE 대기는 "바깥 주소:포트:spi" 로(집 사설 주소가 같은 노트북끼리), SPI 에 클라이언트 MAC 을 섞는다(SPI 는 클라이언트가 정하고 서버는 받은 것을 쓰므로 이중화 쌍끼리 겹칠 일이 없다). 받은 ESP 는 SPI 까지 맞아야 그 클라이언트 것이고, 노트북도 지금 SA 의 SPI 인 ESP 만 푼다(아니면 `vpn.drop` 후 드롭). 노트북의 IKE 포트(500·4500)로 온 서버의 IKE 응답이 지금 SPI 가 아니면(DPD 를 기다리다 "다시 연결" 한 뒤 늦게 온 DPD 응답 등) `RaClient.handleIke` 가 받아 "지난 교환의 늦게 온 응답 → 무시" 로 끝낸다 — 호스트로 넘기면 "UDP 포트를 듣는 프로그램 없음" + ICMP Port Unreachable 이 샌다. "다시 연결" 은 DPD 대기도 정리한다. 풀 안 출발지의 모르는 ESP 는 INVALID_SPI(INFORMATIONAL 응답)로 알려 클라이언트가 다시 접속(서버 설정 변경·이중화 전환 복구). 이중화 master 에서 물러나면 서버는 붙어 있던 클라이언트 터널·진행 중인 협상을 비운다(`RaServer.dropAll`, 임대 기록은 남김) — preempt 로 옛 master 가 돌아와도 노트북은 INVALID_SPI → 다시 접속으로 복구된다. 풀이 다 차면 붙어 있지 않은 클라이언트의 옛 임대를 넘긴다. 실패하면 자동 재시도 없음 — "다시 연결"(`ra-reconnect` 동작). 사이트 간·원격 접속이 바깥 송신 `tunnelIo` 를 같이 쓴다. 구성 검사 `ra.no-routes`·`ra.pool-invalid`·`ra.pool-overlap`(범위 전체, 사이트 간 상대 대역 포함)·`ra.server-off`·`ra.psk-mismatch`·`ra.no-account`(서버가 계정을 요구하는데 클라이언트에 없음)·`ra.account-mismatch`(목록에 없거나 비밀번호가 다름) — 서버 쪽 규칙은 이중화 쌍이면 둘 다 보고, 서버 공인 주소의 장비가 원격 접속을 켜지 않은 NAT 박스이고 UDP 500 을 포워딩하면 그 대상을 서버로 본다(대상이 토폴로지에 없으면 침묵). 불러올 때 `normalizeRaServer`·`normalizeRaClient`(예전 저장본은 계정 없음 = PSK 만). 손으로 고친 JSON 의 숫자 사용자 이름·비밀번호(`1234`)는 문자열로 살리고, `users` 가 객체 하나면 배열로 감싸며 그 밖(문자열·null 등)은 `[]` — **`[]` 면 계정 인증 없이 PSK 만으로 접속된다**. 예제 "재택근무 원격 접속 VPN"(계정 kim·lee, 노트북은 kim).
- 공유기 VPN 서버(`nodes/l2tp.ts`, ipTIME 식 L2TP/IPsec): 서버 `L2tpServer`(공유기 `RouterSettings.vpnServer {enabled, psk, poolStart, poolEnd, users}` — ipTIME 설정 화면의 세 칸), 클라이언트 `L2tpClient`(호스트 `RaClientSettings.type: "l2tp"`, 없으면 IKEv2 — `Host.ra` 는 종류에 따라 `RaClient`/`L2tpClient` 를 바꿔 낀다, 바꿀 때 붙어 있던 쪽을 끊음). 협상: IKEv1 Main Mode 두 교환(NAT 감지 → PSK, 실제 6개 메시지를 축소) → Quick Mode(UDP 1701 을 보호할 ESP **전송 모드** SA, `EspPacket.transport`, NAT 면 UDP 4500) → 그 안에서 L2TP SCCRQ/SCCRP·ICRQ/ICRP → PPP LCP → CHAP(MS-CHAPv2 축소, 계정 필수) → IPCP(할당 IP + DNS = 공유기 LAN 주소면 DNS 포워더) → 데이터는 PPP `{proto: "ip"}`. 패킷 `L2tpPacket`·`PppFrame`(packet.ts), `IkeMessage.exchange` 에 `MAIN_MODE`·`QUICK_MODE`, `l2tp: true`. 클라이언트 L2TP·PPP 요청은 1초·2번 재전송(timer data `{l2tp, phase, tries, id}`, 태그는 `RA_TIMER_TAG` 공유). 공유기: WAN 에서 IKE(`m.l2tp`)·내 SA 의 ESP 를 포트 포워딩·NAT 역변환보다 먼저 받고, 풀린 패킷은 `routeFromVpn`(공유기 자신 DNS·ping, 집 LAN 은 TTL 감소 후 LAN 으로, 다른 VPN 기기, 나머지는 `forwardToWan` — 방화벽·NAT 로 집 공인 주소). 할당 주소는 `NetInterface.proxyArp` 로 공유기가 대신 ARP 응답하고, `lan.outbound` 훅이 그 주소로 가는 패킷(DNS 포워더 응답·ping 응답·Time Exceeded)을 터널로, LAN 기기·NAT 역변환에서 온 것은 `toVpnClient`(TTL 감소). 노트북은 full tunnel: 터널 자신·서버·브로드캐스트·직접 연결된 서브넷만 빼고 출발지를 할당 주소로 바꿔 터널로, 연결된 동안 리졸버는 IPCP DNS(`DnsResolver.vpnDns`). 다시 붙으면 같은 주소, 계정 목록만 바뀌면 세션 유지. 거절은 기억한다: PSK 거절 뒤에도 Main Mode 협상 기록을 남기고, CHAP 실패·IPCP Nak 이면 SA 를 `failed`(표·`connected` 에서 빠짐)로 두어 거절이 사라져 같은 요청이 다시 오면 같은 거절을 다시 보낸다(ravpn `lastAuth` 와 같은 이유 — 아니면 노트북이 "응답 없음 … UDP 500·4500" 으로 원인을 잘못 짚는다). 노트북이 끄면 StopCCN + IKE INFORMATIONAL(Delete). 서버가 상태를 잊을 때 노트북에 알리는 길: 설정 변경·끔이면 L2TP 터널을 연 연결마다 StopCCN 을 보내고 비움(노트북은 "끊김 · 공유기가 연결을 끊음", 자동 재시도 없음 — "다시 연결"), 자동(DHCP) WAN 링크 다운이면 말없이 비우고 그 뒤 모르는 SPI 의 L2TP ESP(전송 모드)가 오면 INVALID-SPI(INFORMATIONAL 응답) → 노트북이 다시 접속. 수동 WAN 은 링크가 깜빡여도 세션 유지(주소가 그대로). L2TP 가 아닌 모르는 ESP 는 NAT 역변환·포워딩으로(공유기 뒤 IKEv2 서버). VPN 서버가 꺼진 공유기에 L2TP IKE 요청이 오면(그 포트 UDP 포워딩이 없을 때) "VPN 서버가 꺼져 있어 받지 않음" 으로 드롭. 할당 IP 인데 붙은 기기가 없는 목적지(끊긴 기기의 프록시 ARP 가 남은 LAN 장치)는 그렇게 기록하고 드롭, VPN 기기가 보낸 패킷의 LAN ARP 실패는 Host Unreachable 을 터널로. 할당은 범위를 LAN 호스트 주소로 잘라 훑는다(한 칸씩 건너뛰면 잘못 넣은 시작에서 수십억 번). 호스트는 지금 VPN 클라이언트가 받지 않은 IKE·ESP(끈 뒤·종류를 바꾼 뒤 늦게 온 것)를 Port Unreachable 없이 버린다. 패킷 상세의 ESP 전송 모드는 안쪽 IP 헤더 없이 "ESP 안 · UDP 1701" 부터. DPD·재협상·LCP 협상·L2TP 신뢰성 채널(Ns/Nr)·Hello 없음. 실무 로그 `l2tpLines`(packetView: charon IKEv1·xl2tpd·pppd). 구성 검사 `router.vpn-pool`(범위 오류·LAN 밖·공유기 주소 포함·DHCP 범위와 겹침·같은 LAN 세그먼트의 고정 주소가 범위 안)·`router.vpn-no-users`, 클라이언트 쪽은 `ra.server-off`·`ra.psk-mismatch`·`ra.no-account`·`ra.account-mismatch` 를 공유기 수동 WAN 주소 기준으로(자동 WAN 이면 침묵, VPN 서버를 안 켠 공유기가 UDP 500 을 포워딩하면 그 대상 공유기를 따라감 — 대상을 모르면 침묵), 종류가 다르면 `ra.type-mismatch`(공유기가 UDP 500 을 안쪽으로 포워딩하면 IKEv2 는 그쪽이 받으므로 침묵). **점검 항목: 새 VPN 협상(종류)을 넣으면 ① 마지막 응답(거절 포함)이 사라질 때 같은 응답을 다시 보내는가 ② 서버가 상태를 잊을 때(설정 변경·재시작·주소를 잃음) 클라이언트가 알게 되는 길이 있는가 ③ 끊은 뒤·종류를 바꾼 뒤 늦게 온 패킷이 Port Unreachable 로 새지 않는가 ④ 구성 검사가 포트 포워딩(공유기 뒤 공유기)을 따라가는가 — 원격 접속 VPN 리뷰에서 나온 것을 L2TP 에서 그대로 되풀이했다(`docs/LESSONS.md` 4u).** 예제 "ipTIME 공유기 VPN (L2TP/IPsec)"(호텔 NAT 뒤 노트북 → 집 ipTIME 203.0.113.20 → 집 NAS, 계정 me). 한계: 출장지 LAN 과 집 LAN 대역이 같으면 집 장치가 직접 연결된 서브넷으로 보여 터널로 안 감(실제와 같음, TROUBLESHOOTING).
- WireGuard(`nodes/wg.ts`, 2026-10-07, GL.iNet Brume 3 계획 1단계 — `docs/ROADMAP.md` 맨 위): `WgInterface`(wg0 하나: 피어마다 엔드포인트·세션·대기열, `WgMessage` initiation 148B·response 92B·data/keepalive, UDP 51820). 키는 결정론(`wgPrivateKey(seed)`·`wgPublicKey(priv)` — 해시 흉내, base64 44자), 모델은 `wgKeyOf(d, role)`(설정에 없으면 `${id}:server|client|host`). 응답자는 mac1(`to` = 내 공개 키)과 피어 목록(`static`)을 확인하고 아니면 **침묵**(trace `reason: mac1|unknown-key`) → 클라이언트는 5초·3번 뒤 실패(실제는 90초), 보낼 패킷이 또 생기면 다시 시도. cryptokey routing: 보낼 때 AllowedIPs 최장 일치, 받을 때 안쪽 출발지가 그 피어의 AllowedIPs 안이어야. 엔드포인트 로밍(`vpn.roam`). passive keepalive(받은 뒤 10초)·응답 없으면 재핸드셰이크(보낸 뒤 15초)는 **배경 타이머**. 설정 변경은 바뀐 피어의 세션만 버린다(꺼진 채 칸만 바뀌면 조용히). 세션은 두 칸(현재·직전 `prevSession` — 동시에 핸드셰이크해도 엇갈리지 않게, 응답자 역할에서도 내 pending 을 지우지 않는다). 바깥 송신은 WAN 링크가 살아 있을 때만(수동 WAN 은 케이블 없이도 주소가 있다), 링크가 올라오면 다시 잇는다. 공유기(`Router`): 서버 `wgs`(`RouterSettings.wgServer {address, port, peers[{name, publicKey, ip}], lanAccess}` — 피어 AllowedIPs = ip/32, 풀린 패킷은 `routeFromWg`: 공유기 자신(DNS 는 서버 터널 주소로 와도 그 주소로 답 — `DnsServer.answersAt`)·다른 피어·LAN(`lanAccess`)·인터넷(NAT), 피어행은 `lan.outbound`·`forwardToWan`·NAT 역변환 뒤 `toWgPeerFwd`), 클라이언트 `wgc`(`wgClient {server, port, serverKey, address, allowedIps, dns, killSwitch, policy {mode all|exclude|only, devices}}` — LAN 기기 패킷은 `natVpn`(터널 주소로 MASQUERADE) 뒤 터널로, 끊기면(핸드셰이크 실패) 킬 스위치가 붙잡고(`vpn.killswitch`) 꺼져 있으면 WAN 으로 샘(`vpn.leak` + 다시 연결 시도). DNS 포워더는 VPN DNS 에 터널로(`DnsServer.upstreamFor(client)`·`upstreamPath.send(…, client)` — 질의한 기기가 VPN 정책에서 빠졌으면 WAN 으로, DNS 유출 방지). 터널 주소가 비면 킬 스위치가 붙잡는다. 서버의 터널 주소(10.0.0.1)는 LAN 에서도 공유기 자신(ping·DNS), 피어가 없는 터널 주소는 Unreachable, LAN 의 장비가 내 공인 주소로 보낸 WireGuard 는 바로 받는다(공유기 뒤 클라이언트 — 답은 LAN 으로). 복사(`cloneDevices`)는 개인 키를 빼 새 신원으로. WAN DHCP 를 받으면 연결, 사용자 동작 `ra-reconnect` 는 공유기면 `wgReconnect`). 노트북·폰: `WgClient`(원격 접속 VPN 종류 `"wireguard"`, `RaClientSettings.wg`) — 주소를 받아 오지 않고 설정 파일의 터널 주소, 켜 두면 AllowedIPs 행은 늘 터널로(새지 않음), 주소가 바뀌어도 세션 유지(로밍). 구성 검사 `lint/wg.ts`: `wg.server-off`·`wg.port-mismatch`·`wg.server-key`·`wg.not-registered`·`wg.address-mismatch`·`wg.dns-outside`·`wg.overlap`·`wg.peer-duplicate`·`wg.peer-key-duplicate`·`wg.peer-in-lan`·`wg.peer-outside`·`wg.no-address`·`wg.no-peers` (UDP 포워딩을 따라감). 실무 출력 `wgLines`(커널 wireguard dyndbg). UI `inspector/wg.tsx`(내 공개 키·복사·다시 만들기, "서버 가져오기" = 서버 피어 등록 + 클라이언트 칸 채우기를 되돌리기 한 단계로). 타일 배지 `WG 서버 n`·`VPN 연결됨`·`킬 스위치`. 예제 "GL.iNet 식 VPN 게이트웨이 (WireGuard·킬 스위치)"(`examples/vpn.ts`). 생략: 쿠키, rekey(2분), 세션 폐기(3분), PersistentKeepalive 주기, IPv6.
- OpenVPN(`nodes/openvpn.ts` `OvpnServer`·`OvpnClient`, 2026-10-07, Brume 계획 6단계): 공유기 `RouterSettings.ovpnServer {enabled, proto udp|tcp, port, subnet, lanAccess, redirectGateway, pushDns, tlsCrypt, users[], revoked[]}`("VPN" 묶음), 노트북·폰 `HostSettings.ra.type: "openvpn"` + `ra.ovpn {proto, port, ca, cn, certCa, tlsCrypt}`(server = remote, 주소 또는 이름, user·password = auth-user-pass). CA·tls-crypt 키는 서버 공유기 id 에서(`ovpnCaOfDevice`·`ovpnTlsCryptOfDevice` — 복사한 공유기는 새 CA), 인증서는 `{cn, ca}`(발급 CA 지문). 패킷 `OvpnMessage`(UDP payload `ovpn` 또는 `TcpSegment.ovpn`). 협상: HARD_RESET → TLS(서버 인증서 → 클라이언트 인증서·계정 → 결과) → PUSH_REQUEST/REPLY(가상 주소 = 대역 .2 부터, CN 마다 같은 주소, 경로·DNS·redirect-gateway). tls-crypt 키가 다르면 서버가 침묵(timeout), CA 가 다르면 노트북 VERIFY ERROR, 다른 CA 인증서·폐기(CRL)·계정 틀림은 서버가 거절(`tls-fail`, 상태 표에 거절 기록). 제어 요청은 1초·2번 재전송, 서버는 같은 요청에 보냈던 답을 다시 보낸다. TCP 모드는 이 모듈이 TCP 를 흉내(3-way·seq/ack·FIN·RST, 재전송은 OpenVPN 층) — NAT·방화벽·DPI 는 보통 TCP 로 본다. keepalive: 클라이언트가 10초 동안 보낸 게 없으면 ping(서버가 ping 으로 답), 60초 동안 받은 게 없으면 다시 연결(배경 타이머). 서버 설정이 바뀌면 붙은 클라이언트에 RESTART(UDP)·RST(TCP) → 2초 뒤 다시 연결, 연결 중 RST 는 실패(DPI·방화벽). 같은 CN 이 다른 곳에서 붙으면 앞 세션에 `exit kicked` → 다시 붙지 않음(서로 밀어내기 방지). WAN 주소가 바뀌면 세션을 비운다(클라이언트는 ping-restart). 공유기 라우팅은 WireGuard 서버 경로를 같이 쓴다(`toTunnelPeer`·`isTunnelPeer`·`routeFromWg(…, vpn)`), 서버 터널 주소의 DNS 포워더. DPI 는 opcode 모양으로 OpenVPN(포트 443 이어도). 구성 검사 `lint/ovpn.ts`: `ovpn.subnet-invalid`·`ovpn.overlap`·`ovpn.port-clash`·`ovpn.incomplete`·`ovpn.name-unknown`·`ovpn.server-behind-nat`·`ovpn.server-off`·`ovpn.proto-mismatch`·`ovpn.tls-crypt-mismatch`·`ovpn.ca-mismatch`·`ovpn.cert-foreign`·`ovpn.revoked`·`ovpn.no-account`·`ovpn.account-mismatch`·`ovpn.duplicate-cn`(포트 포워딩·DDNS 이름을 따라감). 실무 출력 openvpn 로그(VERIFY OK·PUSH_REPLY·Initialization Sequence Completed·tls-crypt unwrap error). 타일 배지 `OpenVPN n`, 표 "OpenVPN 클라이언트 (status)". 예제 "OpenVPN (인증서·tls-crypt·TCP 443)"(`exampleOpenVpnTopology` — 카페 방화벽이 TCP 80·443 만 허용). 서버 재시작은 협상 중인 세션에도 알리고(UDP RESTART, TCP 는 RESTART 뒤 RST), 알림 없는 RST 는 중간 장비 탓으로 본다. 클라이언트는 잊은 TCP 연결(종류 바꾸기·케이블·ping-restart)의 포트를 기억해 늦은 세그먼트를 호스트 TCP 로 넘기지 않는다(`tcpKeys`, `Host.ovpnLate`). 서버 이름 풀기 실패는 2초 뒤 두 번 더 풀고, 주소를 다시 얻으면 처음부터. 서버 세션은 받은 주소(`local`)에서 답한다(멀티 WAN 의 WAN2 로 맺은 연결). 생략: 공유기 OpenVPN 클라이언트, 데이터 채널 키 교환·재협상, 압축, TAP, client-to-client, 서버 쪽 ping-restart. 알려진 한계: "설정 파일 가져오기" 는 서버 공유기가 다른 공유기 뒤에 있으면 그 사설 WAN 주소를 넣는다(DDNS 를 켜면 이름) — WireGuard "서버 가져오기" 도 같다.
