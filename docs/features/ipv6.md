# IPv6 — 링크 로컬·NDP·SLAAC·듀얼 스택·공유기·인터넷 IPv6

기능별 구현 상세 (예전 AGENTS.md "시뮬레이션 연결 방식" 에서 옮김 — 2026-10-07). 규칙·공통 메커니즘은 AGENTS.md.

- IPv6(`docs/ROADMAP.md` "IPv6 계획", 4단계 모두 완료): 장치별로 켠다(`HostSettings.ipv6`, `L3Settings.ipv6`, 없으면 꺼짐 — 기존 구성의 로그 불변). 켜면 MAC 에서 EUI-64 로 만든 링크 로컬(fe80::)이 생기고 모든 주소는 DAD(출발지 :: 의 NS, 1초) 뒤에 쓴다. 이웃 찾기는 NS(목적지 = 대상의 solicited-node 멀티캐스트, MAC 33:33:ff:…) → NA(유니캐스트), 이웃 캐시는 ARP 캐시와 같은 60초. NIC 는 내 MAC·ff02::1·내 주소들의 solicited-node 그룹(라우터는 ff02::2 도)만 받는다(`Ipv6Interface.accepts`). 스위치는 멀티캐스트 MAC 을 브로드캐스트처럼 플러딩(스누핑 없음), AP 도 무선 단말 사이로 중계, 투명 방화벽은 NDP 를 ARP 처럼 통과시키고 나머지 IPv6 는 규칙대로. 출발지 고르기는 RFC 6724 축소판(링크 로컬·ff02:: → 링크 로컬, 아니면 목적지와 가장 길게 겹치는 글로벌) — 글로벌이 없으면 다른 네트워크로 못 나간다. 게이트웨이 `forward6`: 링크 로컬 출발지·목적지와 멀티캐스트는 넘기지 않음, Hop Limit 감소·0 이면 ICMPv6 Time Exceeded, 경로 조회는 연결된 프리픽스 → IPv6 스태틱 라우팅(최장 일치, `::/0` = 디폴트 라우트, 넥스트 홉은 연결된 프리픽스 안의 글로벌 주소), 없으면 Unreachable(no route), NS 무응답이면 Unreachable(address unreachable). NAT 는 IPv6 를 변환하지 않는다(NAT 박스도 주소 그대로 — 바깥에서 안쪽 글로벌 주소로 바로 들어오므로 막는 건 방화벽). 방화벽 규칙의 CIDR 은 IPv6 도 받고 "ICMP" 규칙은 ICMPv6 에도 걸린다. ping·traceroute·TCP 가 IPv6 주소를 받는다(연결 id·표시는 `[주소]:포트`, `tcp.endpoint`). 호스트 기본 게이트웨이는 라우터의 글로벌·링크 로컬 어느 쪽이든. 로드밸런서·프록시·VPN·이중화·RIP·DHCP 릴레이·VLAN 서브 인터페이스는 IPv4 만. 수동 주소는 DAD 를 통과하면 요청하지 않은 NA(ff02::1, O=1)로 알린다(IPv4 의 Gratuitous ARP — 같은 주소로 장비를 바꿔 끼워도 이웃 캐시가 바로 고쳐짐. 링크 로컬·SLAAC 는 MAC 에서 나와 장비가 바뀌면 주소도 바뀌어 알리지 않음). **SLAAC**(2단계): 호스트 `mode: "slaac"`(IPv6 를 켤 때 기본), 게이트웨이 인터페이스별 `ra`(RA 광고)와 장치 `raDns`(RDNSS). 호스트는 링크 로컬 DAD 뒤 RS(ff02::2, 4초 간격 3번까지, 그 뒤 `slaac.timeout`) → RA(ff02::1, 출발지는 라우터 링크 로컬)의 A 플래그 프리픽스가 /64 면 프리픽스 + EUI-64 주소를 만들어 DAD, RA 출발지를 기본 게이트웨이 후보로(`routers`, 수동 게이트웨이가 우선), RDNSS 를 DNS 로. /64 가 아니면 주소를 만들지 않는다. 라우터는 링크 로컬 DAD 가 끝날 때·설정이 바뀔 때(프리픽스·DNS·켜기)·RS 를 받을 때 RA — **주기 RA·수명 만료 없음**(시계 구조): 대신 RA 를 끄거나 IPv6 를 끄거나 장치를 지울 때 라우터 수명 0 + 알렸던 프리픽스 유효 수명 0 인 "거둠 RA" 를 보내고, 프리픽스가 바뀌면 빠진 것을 유효 수명 0 으로 싣는다 → 호스트는 게이트웨이·주소를 지운다. 수동 호스트·라우터는 RA 로 주소를 만들지 않는다. 링크 다운이면 RA 로 배운 것을 잊고 다시 붙으면 RS 부터. 프리픽스마다 알린 라우터를 기억해 모두 거둬야 주소를 지우고(`prefixRouters`), 실행 중 주소가 사라지면 `onAddrRemoved` 로 호스트가 그 주소의 TCP·traceroute 를 정리한다. RDNSS 는 알려 준 라우터가 거두거나 DNS 없이 다시 알리면 지운다. 말없이 사라진 라우터(2026-09-30): 호스트는 RA 의 라우터 수명이 다하면 그 라우터를 뺀다(배경 타이머 `ROUTER_EXPIRY_TAG`, RA 마다 다시 잼, Map 순서 유지라 기본 게이트웨이는 그대로) — 라우터 설정 `Ipv6L3Settings.raPeriodic`(기본 꺼짐)이면 10초마다 주기 RA(배경 타이머)·수명 30초(radvd 3배), 꺼져 있어도 600초마다(radvd 기본 MaxRtrAdvInterval) 다시 알리고 수명 1800초 — 살아 있는 라우터를 수명 만료로 잃지 않게(인터넷 노드의 조용한 ISP 링크도 RS 에 한 번 답한 뒤부터). 기본 게이트웨이 선택은 RFC 4861 6.3.6: 닿지 않은 라우터(NUD 실패·NS 무응답)는 지우지 않고 `suspect` 로 표시해 목록 뒤로 미루고, 의심 없는 첫 라우터를 쓴다(모두 의심이면 맨 앞 — 실패할 때마다 뒤로 가니 돌아가며 고른다). 그 라우터의 RA·요청한 NA 를 받으면 다시 믿는다. 그래서 NUD 를 꺼도 이웃 캐시가 만료돼 다시 물을 때(60초) NS 에 답이 없으면 다른 라우터로 넘어간다. 호스트 설정 `nud`(기본 꺼짐)면 RFC 4861 NUD: 요청한 NA 로 확인한 지 30초 지나면 STALE(RA·NS·요청하지 않은 NA 로 배운 새 항목도 STALE), 보낼 때 DELAY 5초 → PROBE 유니캐스트 NS 3번(1초) → 실패면 이웃 항목을 지우고(`ndp.timeout` nud failed) 라우터면 뒤로 미뤄 다음 라우터로. NUD 타이머는 보낼 때만 걸리는 일반 타이머. 꺼져 있으면 예전처럼 60초 지나면 다시 묻는다. 실무 출력 `ip -6 neigh` 상태 줄(NUD 를 켜면 이웃 캐시 추가 줄도 실제 상태), `ip -6 route` 의 `expires` 는 받은 라우터 수명. 한계: 유효 수명 0 을 즉시 반영한다(실제 리눅스는 2시간 규칙), 프리픽스 수명·RDNSS 수명은 다루지 않는다, TCP 진행 같은 상위 계층 확인은 쓰지 않는다(NA 만). M/O 플래그는 늘 0(DHCPv6 없음). 구성 검사 `lint/ipv6.ts`: `ipv6.duplicate`(케이블·무선으로 이어진 묶음 안에서만)·`ipv6.gateway-off-link`·`ipv6.gateway-unknown`·`ipv6.router-off`·`ipv6.prefix-mismatch`·`ipv6.slaac-no-ra`·`ipv6.ra-prefix`(자동 호스트가 있는 링크에 /64 가 아닌·주소 없는 RA) — 자동 호스트는 주소를 모르므로 게이트웨이·프리픽스 규칙에서 빠진다. **듀얼 스택**(3단계): `DnsMessage.qtype`(A/AAAA, 없으면 A)·`rcode: "NODATA"`(이름은 있지만 그 종류 레코드 없음 = NOERROR 답 0개). DNS 서버 레코드는 주소 모양으로 A/AAAA(같은 이름에 둘 다 가능), 이름은 있는데 종류가 없으면 업스트림에 묻지 않고 NODATA, 캐시 키는 종류별, 질의가 온 IP 버전으로 답하고 IPv6 업스트림도 된다. 리졸버는 IPv4 DNS 가 있고 내 IPv4 주소가 있으면 그쪽, 아니면 IPv6 DNS(수동 `ipv6.dns` 또는 RDNSS)에 묻는다 — 질의 종류와 운반 버전은 따로. 호스트 이름 해석(`Host.resolveName`, getaddrinfo 흉내): IPv6 글로벌 주소가 있으면 AAAA 먼저, 다시 물을 만한 실패(`ResolveInfo` 의 nodata·retry = NODATA·timeout·SERVFAIL·닿지 않음)면 IPv4 주소가 있을 때 A 로 다시 — NXDOMAIN·설정 없음·취소(`clear` 는 목록을 떼어 낸 뒤 콜백)는 다시 묻지 않는다. AAAA 는 있지만 IPv6 기본 게이트웨이가 없고 같은 링크도 아니면 A 로(RFC 6724 규칙 1). 글로벌이 없으면 예전처럼 A 만(기존 로그 불변). ping·traceroute 는 고른 주소로 끝(폴백 없음), TCP 는 이름으로 연 IPv6 연결이 연결 전 단계에서 실패(timeout·Unreachable·RST)하면 A 로 다시 연결(`tcp.fallback`, Happy Eyeballs 축소판 — 실제는 250ms 경주), 답을 기다리는 동안 IPv6 출발지가 사라져도 A 로. **공유기·인터넷 IPv6**(4단계): 인터넷 노드는 늘 IPv6 를 갖지만 조용하다(`Ipv6Interface.startQuiet` — DAD·먼저 보내는 RA 없음, RS·NS·DHCPv6 에만 답해 IPv6 를 안 쓰는 구성의 로그 불변). ISP 링크 2001:db8:ffff::1/64(RA + RDNSS 2001:4860:4860::8888), DHCPv6-PD 서버(`Dhcp6Message`, UDP 546/547, ff02::1:2 — 풀 2001:db8:1000::/40 에서 고객 MAC 마다 /56, Request 에 Reply 하며 "위임 = 경로": `delegations` 프리픽스 → 고객 WAN 링크 로컬, Release·회선 끊김에 삭제), 공인 IPv6(글로벌이면서 2001:db8::/32 가 아닌 주소)에 ping·TCP 80/22 응답, 공인 IPv6 DNS 2001:4860:4860::8888·2606:4700:4700::1111, 공개 이름 AAAA(`PUBLIC_ZONE6` — github.com·naver.com 은 실제처럼 AAAA 없음 → NODATA). ISP 는 위임한 프리픽스·ISP 링크 밖의 출발지를 버린다(게이트웨이·NAT 박스에 손으로 넣은 IPv6 는 인터넷에 못 나감 — PD 클라이언트는 공유기만). 바깥 클라이언트 IPv6 2001:db8:beef::7(`inet-connect` 에 IPv6 주소). 공유기 `RouterSettings.ipv6 {enabled, inboundBlock}`: WAN(`wan6`, 호스트처럼 SLAAC)이 ISP RA 로 주소·기본 게이트웨이, 링크 로컬이 준비되면(`onLinkLocalReady`) `Dhcp6PdClient`(nodes/dhcp6.ts, Solicit→Advertise→Request→Reply, 1초·3번) → 위임받은 /56 의 첫 /64 를 LAN(`lan6`) 주소 ::1 로 두고 RA(RDNSS = 공유기 LAN 주소 — DNS 포워더가 IPv6 로도 답함). 위임 전에는 RA 를 하지 않고(`raOffReason`), WAN 링크 다운·IPv6 끔이면 거둠 RA. 전달은 NAT 없이 주소 그대로(Hop Limit 만), 사용자 방화벽 규칙 + `inbound6`(“IPv6 기본 방화벽”: 규칙 없이 기본 차단, 나가는 흐름은 `Firewall.remember` 로 조용히 기억 → 응답만 들어옴). 공유기 방화벽의 인바운드 허용 규칙이 일치하면 그것이 핀홀(`Firewall.allowsByRule` → 기본 차단 건너뜀). 끄면 바깥에서 집 안 장치로 포트 포워딩 없이 바로 들어온다. 위임받은 /56 안이지만 LAN /64 가 아닌 목적지는 Unreachable(no route)(RFC 7084 WPD-5). ISP 는 회선이 끊겨도 위임을 지우지 않는다(IPv4 임대처럼). 한계: 스위치 너머에서 인터넷 노드를 지웠다 되돌리면 공유기가 모른다 — ISP 드롭 로그가 "공유기 WAN 을 다시 꽂으라" 고 안내. 인터넷 노드 "외부에서 접속" 목록에 위임 프리픽스 안의 호스트 IPv6 주소. 구성 검사: 공유기 LAN 을 RA 라우터로 보고(프리픽스는 PD 라 `ra-prefix` 제외), IPv6 를 끈 공유기 LAN 의 자동 호스트는 `ipv6.router-off`. 예제 "IPv6 기초 (링크 로컬·NDP·라우팅)"(IPv4 없이, 수동)·"IPv6 자동 주소 (SLAAC·RA)"·"듀얼 스택 사무실 (A·AAAA·Happy Eyeballs)"·"듀얼 스택 집 (NAT 없는 IPv6·프리픽스 위임)". 트레이스 `ndp.*`(ICMPv6 위라 L3)·`slaac.*`. 타일은 IPv6 주소의 /64 를 뺀다(폭)
