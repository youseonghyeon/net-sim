# L2 — 무선·VLAN·STP·IGMP 스누핑

기능별 구현 상세 (예전 AGENTS.md "시뮬레이션 연결 방식" 에서 옮김 — 2026-10-07). 규칙·공통 메커니즘은 AGENTS.md.

- 무선: 모델의 `wirelessLinks(topology)` 가 SSID·거리(`WIFI_RANGE`)로 단말→기지 연결을 파생하고, `sim.ts` 가 이를 `wl_<단말id>_<기지id>_<슬롯>` 케이블로 `Network` 에 넣는다(지연 20ms, 기지·슬롯이 바뀌면 다른 링크로 보고 재연결). 기지 포트는 `PortSpec.radio`(그리지 않음, 케이블 금지). 코어 `AccessPoint`(포트 0 = eth0, 1..8 = 무선 슬롯), `Router.RADIO_PORTS`(5..12). 슬롯 할당은 `slotTable` 로 안정화. 단말의 무선 포트는 `WirelessLink.clientPort`(스마트폰 0, 노트북 1). **노트북 유선·무선 NIC**(2026-10-01): 포트 0 = eth0(유선), 1 = wlan0(무선, `PortSpec.radio`). Wi-Fi 는 `Device.wifi`(없으면 꺼짐, `enabled: false` = 꺼짐이지만 SSID 기억 — 기존 구성의 로그 불변)로 켠다. 코어 `Host` 는 `HostConfig.wlanMac`(`wlanMacOf` — 유선 MAC 의 4번째 옥텟 02)이 있으면 `nics` 둘, IP 스택은 하나: 유선 링크가 살아 있으면 유선, 아니면 무선을 쓴다(`activeNic`, 인터페이스 메트릭의 유선 우선 흉내). 바꿔 낄 때는 원인 줄("eth0 링크 다운" / "eth0 링크 연결됨 → 유선이 우선이라 … 내려놓음") 뒤 쓰던 쪽을 바로 내리고(`stackDown` — TCP·traceroute·VPN·DHCP 주소 정리), 어느 NIC 로 갈지는 0ms 뒤(`NIC_SWITCH_TAG`, `switchNic`) 정한다 — 같은 순간의 다른 링크 변화(공유기를 지워 케이블·Wi-Fi 가 차례로 끊김)까지 본 뒤라 가짜 전환이 없다. 그때 MAC 을 바꾸고(`NetInterface.setMac`·`Ipv6Interface.setMac` — 링크 로컬도 새로) 전환 줄과 함께 다시 올린다(`stackUp`). 지워지는 노트북(`onRemove` 뒤)은 링크가 끊겨도 넘어가지 않는다. DHCP 기억은 NIC 마다(`DhcpClient.remembered`, 지금 MAC 의 NIC 에 저장 — 둘 다 끊긴 상태를 거쳐도) — 유선으로 돌아오면 INIT-REBOOT 로 쓰던 주소를 되찾는다. 무선 슬롯은 먼저 각자 쓰던 슬롯을 지켜 주고 남은 단말이 빈 슬롯을 받는다(쓰는 연결이 대기 연결보다 먼저) — 노트북 Wi-Fi 를 켜도 붙어 있던 스마트폰이 흔들리지 않는다. 쉬는 NIC 로 온 프레임은 IP 스택에 올리지 않는다. 유선을 쓰는 동안 붙어 있는 Wi-Fi 는 `WirelessLink.standby`(캔버스 회색 점선, 기지 표 "대기", 구성 검사 — 세그먼트·`ipv6.duplicate` 묶음 — 는 뺌, 연결 로그 "대기 (주소는 받지 않음)"). 한계: 실제 OS 는 두 NIC 를 동시에 쓰고 메트릭으로 기본 경로만 고르지만, 여기서는 하나만 쓴다(분할 라우팅 없음). 수동 IP 설정은 NIC 하나에 공유. 타일 배지 `Wi-Fi`(무선을 쓰는 중). 원격 접속 VPN 클라이언트의 식별(cid)은 늘 유선 NIC 의 MAC 이라(Wi-Fi 를 쓰는 중에 VPN 종류를 바꿔도) 넘어가도 같은 가상 주소를 받는다.
- VLAN: `EthernetFrame.vlan` 은 802.1Q 태그(트렁크 링크에서만). `Switch.portVlan`(액세스 번호 | "trunk"), MAC 테이블 키 `"vlan:mac"`, 플러딩은 같은 VLAN 액세스 포트 + 트렁크. `L3Node.meta[i] = {port, vlan?}` 로 인터페이스 i 가 물리 포트/태그에 매핑되며 서브 인터페이스는 물리 인터페이스 뒤에 붙는다(`setSubinterfaces`). 호스트·공유기는 태그 프레임을 드롭하고, 허브·AP 는 L1/L2 반복기라 태그를 그대로 넘긴다. 스위치 루프 가드는 `프레임 id + 들어온 VLAN` 으로 본다(투명 방화벽이 한 스위치의 두 VLAN 을 이어도 루프가 아님).
- IGMP 스누핑(`nodes/igmp.ts` `IgmpSnoop`, 2026-10-07, Brume 계획 9단계): IPv4 payload `IgmpPacket {report|leave, group}`(IP 2, `isControl` — 호스트·L3 는 조용히 거름), UDP payload `McastData`(IPTV 조각, 포트 5004), `mcastMac`(01:00:5e + 아래 23비트). 호스트: 사용자 동작 `mcast-join`·`mcast-leave`(Report 는 그룹 주소로, Leave 는 224.0.0.2)·`mcast-send`(조각 5개 100ms 간격 — 일반 타이머, 끝이 있음), 가입한 그룹의 MAC 만 NIC 가 받는다(`Host.groups`, `streamRx`). 스누핑(`SwitchSettings.igmpSnooping`, 공유기 `RouterSettings.igmpSnooping` — 내부 스위치): Report·Leave 를 엿들어 "VLAN:그룹 → 포트" 를 배우고, 스트림은 가입한 포트로만, 가입한 포트가 없는 그룹은 아무 데도 보내지 않는다. 224.0.0.x 링크 로컬 제어(VRRP·RIP)와 IGMP 자체는 늘 플러딩. 링크 다운이면 그 포트를 뺀다. 끄면 예전처럼 모든 포트로(기존 로그 불변). 표 "IGMP 스누핑 (그룹 → 포트)". 리뷰 반영: 스누핑을 켜면 스위치·공유기가 General Query(224.0.0.1, 출발지 0.0.0.0)를 보내 가입한 호스트가 다시 알린다(스누핑 쿼리어), 호스트는 주소를 다시 얻을 때(링크 복구·NIC 전환)도 가입한 그룹을 다시 알리고, 다른 기기의 Leave(224.0.0.2)를 들으면 아직 보고 있는 그룹을 다시 알린다(그룹별 쿼리 흉내 — 허브 뒤·아래 스위치의 다른 가입자가 끊기지 않게). 멀티캐스트 판별은 `isMcastIp`(224~239 전부). `nat.forward-smb` 는 안쪽 포트·NAT 장비도. 생략: 가입 만료·라우터 포트 학습·IGMPv3·MLD 스누핑·멀티캐스트 라우팅. 예제 "IPTV 멀티캐스트와 IGMP 스누핑"(`exampleIgmpTopology`).
- 스패닝 트리(`nodes/stp.ts` `Stp`, 802.1D 축소판): `SwitchSettings.stp {enabled, priority}`(기본 꺼짐 — 실제 스위치는 기본 켜짐이지만 기존 구성의 로그를 바꾸지 않으려고). BPDU 는 이더넷 payload `BpduPacket`(01:80:c2:00:00:00, 802.3+LLC, IP 없음) — 호스트·L3 는 멀티캐스트라 거르고, STP 를 끈 스위치는 멀티캐스트처럼 넘긴다. 포트마다 마지막으로 들은 BPDU 로 루트(브리지 ID 최소)·루트 포트(비용 → 보낸 브리지 → 보낸 포트 → 내 포트)·지정/대체 포트를 계산, 대체 포트는 데이터 프레임을 받지도 보내지도 않는다(`stp.discard`). **주기 BPDU·Max Age 타이머 없음** — 바뀌면 연결된 **모든** 포트로 알린다(지정 포트로만 보내면 루트·차단 포트 건너편의 옛 정보가 영영 안 바뀐다). 같은 순간의 변화는 모아 0ms 뒤 한 번(`stp-send` 타이머 — 큰 그물에서 BPDU 폭주 방지). 받은 정보는 802.1D 처럼 더 좋거나 같은 보낸이의 갱신일 때만 바꾼다(허브에 스위치 셋이면 서로 덮어써 끝없이 돈다). 장치 제거·STP 끔·우선순위 변경 때는 Message Age 21 의 "거둠" BPDU(`withdraw`, 같은 보낸이 것만 지움)로 이웃의 옛 정보를 지우고, 루트가 사라지면 Message Age 20 초과로도 끝난다. STP 를 켠 적 없는 스위치는 조용하다. 토폴로지 변경(역할 변화·전달 포트 끊김)은 MAC 테이블을 비우고 BPDU 의 `tc` 번호로 다른 스위치에도 한 번씩 퍼뜨린다(`stp.tc`). 한 인스턴스(CST)라 VLAN 을 구분하지 않는다. RSTP 처럼 곧바로 전환(30초 대기 없음). 캔버스는 막힌 포트의 케이블에 점선·⊘(`StpBlocks`), 타일 배지 `STP 루트/STP`. 구성 검사 `switch.loop-no-stp`(스위치·허브·공유기 LAN·투명 방화벽 케이블이 이루는 고리에 실제로 속한 STP 끈 스위치 — 케이블 하나를 빼도 두 끝이 이어지면 고리 위). 예제 "스위치 이중화 (STP)".
