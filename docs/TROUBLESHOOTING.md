# 시뮬레이터에서 자주 보는 실패와 원인

통신이 안 될 때 이벤트 로그(하단 서랍)에 남는 문구와 원인, 고치는 법. 실제 네트워크에서도 같은 순서로 의심하면 된다.

## 주소를 못 받는다 ("IP 없음", "DHCP 실패")

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `DHCP 응답 없음 → 재시도 n/3` 뒤 `DHCP 실패` | 같은 L2 세그먼트에 DHCP 서버가 없거나 꺼져 있다 | 라우터의 DHCP 서비스를 켜거나 DHCP 서버 호스트를 두고, 호스트 진단에서 **DHCP 다시 요청** |
| 라우터/서버 쪽 `DHCP 서비스가 꺼져 있음 → 응답하지 않음` | 서버는 Discover 를 받았지만 서비스가 꺼짐 | DHCP 토글 켜기 |
| `빌려줄 주소가 없음 (범위 … 모두 사용 중)` | 풀 고갈. 지운 장치의 임대는 Release 로 돌아오지만, 케이블만 뽑은 장치의 임대는 남는다 | 범위를 넓히거나, 안 쓰는 장치를 삭제(Release) |
| `DHCP 설정 오류: 범위 … 가 인터페이스 서브넷 밖` | LAN 주소를 바꿨는데 범위가 옛 서브넷 | 인스펙터에서 범위를 서브넷 안으로. LAN 주소를 바꾸면 범위는 자동으로 따라오지만 직접 고친 값은 검증 오류로 표시된다 |
| `DHCP 서버가 켜져 있지만 내 주소가 고정이 아님` | DHCP 서버 역할 호스트가 자기 주소를 DHCP 로 받으려 함 | 그 호스트의 IP 설정을 **수동**으로 |
| `DHCP Offer … (게이트웨이 안내 없음)` | DHCP 서버 호스트에 "게이트웨이 안내" 가 비어 있음 → 클라이언트는 같은 서브넷 밖으로 못 나감 | 서버의 게이트웨이 안내 칸에 그 서브넷의 게이트웨이 주소 |
| 주소를 받았는데 옛 서브넷(예: 192.168.0.x) | 라우터 LAN 을 바꾸기 전에 받은 임대 | 호스트에서 **DHCP 다시 요청** (라우터 쪽 옛 임대는 이미 무효화됨) |
| 두 장치가 `주소 충돌: … 도 내 IP 를 쓴다고 알림` | 같은 서브넷에 같은 수동 IP | 하나를 바꾼다 |

## ping 이 실패한다

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `ping … 실패: 내 IP 주소가 없음` | 위 표 참조 | 주소부터 |
| `… 는 다른 서브넷인데 게이트웨이 설정 없음 → 폐기` | 호스트에 게이트웨이가 없음 | 수동이면 게이트웨이 입력, 자동이면 DHCP 서버가 게이트웨이를 안내하는지 확인 |
| `ARP 응답 없음 (…) → 대기 패킷 폐기` / `Destination Host Unreachable` | 그 IP 를 가진 장치가 같은 세그먼트에 없다. **잘못된 게이트웨이 주소**일 때도 이 문구 | 대상/게이트웨이 주소가 실제 장치 주소인지, 같은 서브넷인지 확인 |
| `목적지 … 는 LAN 안의 주소 → 라우터를 거칠 필요가 없음 → 폐기` (라우터) | 호스트 서브넷 마스크가 잘못돼 같은 LAN 인데 게이트웨이로 보냄 | 호스트 프리픽스(/24 등)를 라우터와 맞춘다 |
| `WAN 에 공인 주소가 없음 → 인터넷으로 보낼 수 없음` | 라우터 wan 포트에 인터넷이 안 붙었거나 WAN DHCP 실패 | wan 포트에 인터넷 노드 연결, WAN 설정 확인 |
| `… 에 주소가 없음 (케이블과 DHCP, 또는 수동 주소를 확인)` (게이트웨이/NAT) | 업링크 인터페이스에 주소 없음 | 업링크(if0/outside) 케이블·설정 확인 |
| `경로 없음 … 정적 경로를 추가하세요` (NAT 박스) | NAT 박스 뒤에 게이트웨이가 더 있어, 역변환한 응답을 보낼 안쪽 경로를 모름 | NAT 박스 정적 경로에 `192.168.0.0/16 via <게이트웨이의 업링크 주소>` 처럼 추가 |
| `사설 주소 … 는 인터넷에서 라우팅되지 않음 → 폐기` (인터넷) | NAT 없이 사설 주소가 밖으로 나감 (게이트웨이만 있고 NAT 없음) | 인터넷 앞에 NAT 박스나 라우터를 둔다 |
| `NAT 테이블에 없는 … → 폐기. 내부에서 시작하지 않은 통신은 들어올 수 없음` | 바깥에서 먼저 시작한 통신 | 정상 동작. NAT 의 성질 |
| `바깥에서 안쪽 주소 … 로 온 패킷 → 폐기` | 바깥에서 사설 주소를 직접 찍음 | 정상 동작 |
| `ping … 실패: 2000ms 동안 응답 없음 (Request timed out)` | ARP 는 됐지만 응답이 안 옴: 중간 경로 없음, 케이블 유실 실험, 상대가 폐기 | 중간 장치(라우터/게이트웨이/NAT)의 로그에서 폐기 문구를 찾는다 |
| `프레임이 스위치 16개를 넘게 돌았음` / `같은 프레임을 … 다시 받음 → L2 루프` | 두 장치 사이 케이블 2개, 스위치 삼각형 등 L2 루프 | 중복 케이블 제거. 실제 네트워크는 STP 가 막는다 |
| `이벤트가 폭주해 일시정지했습니다` (토스트) | 위 루프가 심해 시뮬레이션이 스스로 멈춤 | 루프 케이블을 지우고 재생 |

## TCP 연결이 안 된다 / 끊긴다

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `RST 수신: … 그 포트를 듣는 서비스가 없음 → 연결 거부` | 대상의 서비스(웹 서버 80)가 꺼짐, 또는 포트 번호가 다름 | 대상 장치의 서비스 토글 켜기, 포트 확인 |
| `… 재전송 (n/3)` 반복 뒤 `TCP 실패: … ACK 없음` | 경로 어딘가에서 유실(케이블 손실률/유실 실험) 또는 경로 없음 | 케이블 손실률을 0 으로, 또는 ping 으로 먼저 경로를 확인 |
| `순서가 어긋난 데이터 … 중간 세그먼트가 유실됨` | 세그먼트 하나가 유실되어 뒤 세그먼트가 먼저 도착 | 정상 복구 과정. 서버가 타임아웃 후 재전송한다 |
| `종료된 연결로 FIN·ACK 가 다시 옴 → ACK 재전송` | 내 마지막 ACK 이 유실됨 | 정상 복구 과정 |
| `주소 변경` 으로 연결 실패 | 전송 중 IP 모드/주소를 바꿈 | 정상. 다시 연결 |

## 그 밖에

- **시계가 멈춰 있다**: 패킷이 없고 대기 이벤트도 없으면 시계는 일부러 멈춘다. 동작(ping, 케이블 연결)을 하면 다시 흐른다.
- **일시정지 상태에서 아무 일도 없다**: 상단 ▶ 재생 또는 다음 이벤트(→). Space 로 토글.
- **장치가 캔버스 밖에 있다**: 예제를 다시 불러오면 내용에 맞춰 화면을 잡는다. 휠로 이동, ⌘+휠로 확대·축소.
- **케이블이 안 이어진다** ("빈 포트가 없습니다" / "이미 연결되어 있습니다"): 포트 수 한도(호스트 1, 라우터 5, 스위치 8), 같은 두 장치 사이는 케이블 1개만.
