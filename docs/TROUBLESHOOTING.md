# 시뮬레이터에서 자주 보는 실패와 원인

통신이 안 될 때 이벤트 로그(하단 서랍)에 남는 문구와 원인, 고치는 법. 실제 네트워크에서도 같은 순서로 의심하면 된다.

## 주소를 못 받는다 ("IP 없음", "DHCP 실패")

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `DHCP 응답 없음 → 재시도 n/3` 뒤 `DHCP 실패` | 같은 L2 세그먼트에 DHCP 서버가 없거나 꺼져 있다 | 라우터의 DHCP 서비스를 켜거나 DHCP 서버 호스트를 두고, 호스트 진단에서 **DHCP 다시 요청** |
| 라우터/서버 쪽 `DHCP 서비스가 꺼져 있음 → 응답하지 않음` | 서버는 Discover 를 받았지만 서비스가 꺼짐 | DHCP 토글 켜기 |
| `빌려줄 주소가 없음 (범위 … 모두 사용 중)` | 풀 고갈. 지운 장치의 임대는 Release 로 돌아오지만, 케이블만 뽑은 장치의 임대는 남는다 | 범위를 넓히거나, 안 쓰는 장치를 삭제(Release) |
| `DHCP 설정 오류: 범위 … 가 인터페이스 서브넷 밖` | LAN 주소를 바꿨는데 범위가 옛 서브넷 | 인스펙터에서 범위를 서브넷 안으로. LAN 주소를 바꾸면 범위는 자동으로 따라오지만 직접 고친 값은 검증 오류로 표시된다 |
| `DHCP 서버가 켜져 있지만 내 주소가 고정이 아님` | DHCP 서버 역할 호스트가 자기 주소를 DHCP 로 받으려 함 | 그 호스트의 IP 설정을 **수동**으로 |
| `DHCP Offer … (게이트웨이 안내 없음)` | DHCP 서버 호스트에 "게이트웨이 안내" 가 비어 있음 → 클라이언트는 같은 서브넷 밖으로 못 나감 | 서버의 게이트웨이 안내 칸에 그 서브넷의 게이트웨이 주소 |
| 주소를 받았는데 옛 서브넷(예: 192.168.0.x) | 라우터 LAN 을 바꾸기 전에 받은 임대 | 호스트에서 **DHCP 다시 요청** (라우터 쪽 옛 임대는 이미 무효화됨) |
| 두 장치가 `주소 충돌: … 도 내 IP 를 쓴다고 알림` | 같은 서브넷에 같은 수동 IP | 하나를 바꾼다 |

## ping 이 실패한다

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `ping … 실패: 내 IP 주소가 없음` | 위 표 참조 | 주소부터 |
| `… 는 다른 서브넷인데 게이트웨이 설정 없음 → 폐기` | 호스트에 게이트웨이가 없음 | 수동이면 게이트웨이 입력, 자동이면 DHCP 서버가 게이트웨이를 안내하는지 확인 |
| `ARP 응답 없음 (…) → 대기 패킷 폐기` / `Destination Host Unreachable` | 그 IP 를 가진 장치가 같은 세그먼트에 없다. **잘못된 게이트웨이 주소**일 때도 이 문구 | 대상/게이트웨이 주소가 실제 장치 주소인지, 같은 서브넷인지 확인 |
| `목적지 … 는 LAN 안의 주소 → 라우터를 거칠 필요가 없음 → 폐기` (라우터) | 호스트 서브넷 마스크가 잘못돼 같은 LAN 인데 게이트웨이로 보냄 | 호스트 프리픽스(/24 등)를 라우터와 맞춘다 |
| `WAN 에 공인 주소가 없음 → 인터넷으로 보낼 수 없음` | 라우터 wan 포트에 인터넷이 안 붙었거나 WAN DHCP 실패 | wan 포트에 인터넷 노드 연결, WAN 설정 확인 |
| `… 에 주소가 없음 (케이블과 DHCP, 또는 수동 주소를 확인)` (게이트웨이/NAT) | 업링크 인터페이스에 주소 없음 | 업링크(if0/outside) 케이블·설정 확인 |
| `경로 없음 … 정적 경로를 추가하세요` (NAT 박스) | NAT 박스 뒤에 게이트웨이가 더 있어, 역변환한 응답을 보낼 안쪽 경로를 모름 | NAT 박스 정적 경로에 `192.168.0.0/16 via <게이트웨이의 업링크 주소>` 처럼 추가 |
| `사설 주소 … 는 인터넷에서 라우팅되지 않음 → 폐기` (인터넷) | NAT 없이 사설 주소가 밖으로 나감 (게이트웨이만 있고 NAT 없음) | 인터넷 앞에 NAT 박스나 라우터를 둔다 |
| `NAT 테이블에 없는 … → 폐기. 내부에서 시작하지 않은 통신은 들어올 수 없음` | 바깥에서 먼저 시작한 통신 | 정상 동작. NAT 의 성질 |
| `바깥에서 안쪽 주소 … 로 온 패킷 → 폐기` | 바깥에서 사설 주소를 직접 찍음 | 정상 동작 |
| `ping … 실패: 2000ms 동안 응답 없음 (Request timed out)` | ARP 는 됐지만 응답이 안 옴: 중간 경로 없음, 케이블 유실 실험, 상대가 폐기 | 중간 장치(라우터/게이트웨이/NAT)의 로그에서 폐기 문구를 찾는다 |
| `프레임이 스위치 16개를 넘게 돌았음` / `같은 프레임을 … 다시 받음 → L2 루프` | 두 장치 사이 케이블 2개, 스위치 삼각형 등 L2 루프 | 중복 케이블 제거. 실제 네트워크는 STP 가 막는다 |
| `이벤트가 폭주해 일시정지했습니다` (토스트) | 위 루프가 심해 시뮬레이션이 스스로 멈춤 | 루프 케이블을 지우고 재생 |

## 이름(google.com, web.home)이 안 된다

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `… 찾을 수 없음: DNS 서버가 설정되지 않음` | 호스트에 DNS 가 없음 (수동 설정에서 비웠거나, DHCP 서버가 DNS 를 안내하지 않음) | 수동이면 DNS 칸 입력. 자동이면 DHCP 서버(라우터는 자동으로 자기 주소, 호스트 서버는 "DNS 안내" 칸) 확인 |
| `DNS 실패: 서버 … 가 2번 물어도 응답 없음` | DNS 서버 주소가 틀리거나 경로가 없음, 또는 그 호스트의 DNS 서버 서비스가 꺼짐 | 서버 주소 확인, 그 서버로 ping 이 되는지 확인, 서버의 "DNS 서버" 토글 |
| `DNS 응답: … 없는 이름 (NXDOMAIN)` | 서버 레코드에 없고 상위 DNS 도 모르는 이름 | 서버 레코드 추가. 공개 이름은 google.com, example.com, naver.com, github.com, cloudflare.com 만 등록돼 있음 |
| `DNS 서버가 상위 서버 응답을 받지 못함 (SERVFAIL)` / 라우터 `상위 DNS … 응답 없음` | 라우터 포워더나 DNS 서버가 상위(8.8.8.8)에 못 닿음: 인터넷 미연결, WAN 주소 없음 | 인터넷 노드 연결과 WAN/outside 주소 확인 |
| `DNS 포워더가 꺼져 있음` | 라우터의 DNS 포워더 토글이 꺼짐 | 켜거나 호스트에 8.8.8.8 을 직접 설정 |
| `DNS 질의를 받았지만 DNS 서버 서비스가 꺼져 있음` | 호스트를 DNS 로 지정했는데 그 호스트의 서비스가 꺼짐 | 서비스에서 DNS 서버 켜기 |

## 바깥에서 들어오는 연결 (포트 포워딩)

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `NAT 테이블에 없는 TCP 포트 80 → 폐기 … (포트 포워딩 규칙을 추가하면 열 수 있음)` | 바깥에서 시작한 연결에 규칙이 없음 | 라우터/NAT 박스의 포트 포워딩에 `공인 :80 → 내부 서버:80` 추가 |
| 규칙은 있는데 인터넷 쪽 클라이언트가 `실패` | 내부 서버 주소가 틀리거나 서버의 웹 서비스가 꺼짐, 또는 NAT 박스 뒤 라우터로 가는 정적 경로 없음 | 규칙의 주소·포트, 서버의 웹 서버 토글, NAT 박스 정적 경로 확인 |
| `RST 수신 … 그 포트를 듣는 서비스가 없음` (내부 서버) | 포워딩은 됐지만 서버가 그 포트를 안 듣는다 | 서버의 서비스 토글 |

## 방화벽

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `방화벽 차단: 나가는/들어오는 … — 규칙 N (…) → 폐기` | 그 라우터/게이트웨이의 규칙 N 에 걸림 | 규칙을 지우거나 순서를 바꾼다(위가 먼저). 허용 규칙을 차단 규칙보다 위에 |
| `방화벽 차단: … — 일치하는 규칙 없음, 기본 정책 차단` | 기본 정책이 차단인데 허용 규칙이 없다 | 필요한 통신의 허용 규칙 추가(예: 나가는 TCP 80) 또는 기본 정책을 허용으로 |
| 안에서 시작한 ping/TCP 의 **응답**이 `방화벽 차단` | 상태 추적이 꺼져 있어 응답도 "들어오는" 규칙에 걸림 | 상태 추적 켜기. 실제 방화벽의 ESTABLISHED 허용과 같다 |
| `… 상 차단이지만, 안에서 시작한 통신의 응답이라 상태 추적으로 허용` | 정상. 규칙엔 걸리지만 응답이라 통과 | 응답까지 막고 싶으면 상태 추적을 끈다 |
| 포트 포워딩은 됐는데 서버에 안 닿음 | `nat.forward.rule` 뒤에 `방화벽 차단 … 들어오는 TCP …:80` | 방화벽에 들어오는 TCP 80 허용 규칙을 차단 규칙 위에 |
| 게이트웨이에서 서브넷 간 통신이 "들어오는/나가는" 규칙에 안 걸림 | 방향은 업링크(if0/outside/WAN) 기준이라 안쪽 서브넷끼리는 "모든 방향" 만 해당 | 서브넷 간 규칙은 방향을 "모든 방향" 으로 하고 출발지/목적지로 구분 |

## 무선 (Wi-Fi)

| 로그 문구 / 화면 | 원인 | 고치는 법 |
|---|---|---|
| 스마트폰에 `무선 연결 없음`, 인스펙터 "SSID … 를 송출하는 AP 나 공유기가 없습니다" | SSID 오타이거나 기지가 없음 | 단말 SSID 와 AP/공유기 SSID 를 맞춘다 (대소문자 구분) |
| "SSID … 의 무선이 꺼져 있습니다" | 공유기 무선 토글이 꺼짐 (기본값 꺼짐) | 공유기 → 무선(Wi-Fi) 켜기. 무선 AP 장치는 기본 켜짐 |
| "전파 범위 밖입니다" | 단말이 기지 중심에서 300px 넘게 떨어짐 (캔버스의 점선 원 밖) | 단말을 원 안으로 끌어오기 |
| `무선 연결 끊김 (범위 밖이거나 …)` 뒤 `임대 주소 … 해제` | 끌어서 범위를 벗어남 | 정상. 다시 들어오면 재연결 + DHCP 다시 |
| AP 에 붙었는데 주소를 못 받음 | AP 의 eth0 에 케이블이 없음 (AP 는 브리지일 뿐, DHCP 서버가 아님) | AP eth0 을 스위치/공유기에 케이블로 연결 |
| 단말끼리 ping 이 AP 를 거침 (`단말 ↔ 단말 중계`) | 정상. 무선 단말은 서로 직접 통신하지 않고 AP 가 중계한다 | — |
| `전파로 송출 … 다른 단말도 전파는 받지만 암호화되어 읽지 못한다` | 정상. 무선은 같은 채널의 모두에게 닿는다 | — |

## VLAN

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `… 는 트렁크인데 태그 없는 프레임 → 폐기 (상대 포트도 트렁크여야 함)` | 케이블 한쪽만 트렁크 | 양쪽 스위치 포트를 모두 트렁크로, 또는 둘 다 액세스로 |
| `… 는 액세스 포트(VLAN n)인데 VLAN m 태그 프레임 → 폐기` | 트렁크에서 온 태그 프레임이 액세스 포트로 들어옴 | 그 포트를 트렁크로 |
| 호스트 `VLAN n 태그가 달린 프레임 → 호스트는 태그를 이해하지 못해 폐기` | 호스트가 트렁크 포트에 꽂힘 | 호스트 쪽 스위치 포트를 액세스(VLAN 번호)로 |
| 같은 서브넷 주소인데 `ARP 응답 없음` | 두 호스트가 다른 VLAN 포트에 꽂힘 (브로드캐스트 도메인이 다름) | 같은 VLAN 으로 맞추거나, 서브넷을 나누고 게이트웨이로 잇는다 |
| 게이트웨이 `VLAN n 태그 프레임 → 해당 서브 인터페이스 없음 → 폐기` | 트렁크로 들어온 VLAN 에 서브 인터페이스가 없음 | 게이트웨이의 그 인터페이스에 `VLAN n` 서브 인터페이스(주소) 추가 |
| 다른 VLAN 으로 ping 이 `게이트웨이 설정 없음` / `ARP 응답 없음` | 호스트 게이트웨이가 그 VLAN 의 서브 인터페이스 주소가 아님 | 호스트 게이트웨이 = 자기 VLAN 서브 인터페이스 주소 (예: VLAN 10 → 192.168.10.1) |
| 공유기 `LAN 포트는 태그를 이해하지 못해 폐기` | 트렁크 포트를 공유기에 꽂음 | 공유기는 VLAN 미지원. 게이트웨이 장치를 쓰거나 스위치 포트를 액세스로 |

## 허브

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `허브: 학습 없이 … 모든 포트로 반복 — 모든 장치가 이 프레임을 본다` | 정상. 허브는 MAC 을 배우지 않아 모든 프레임을 모두에게 보낸다 | 스위치로 바꾸면 `MAC 테이블 조회 → 해당 포트로만 전달` 로 바뀐다 |

## TCP 연결이 안 된다 / 끊긴다

| 로그 문구 | 원인 | 고치는 법 |
|---|---|---|
| `RST 수신: … 그 포트를 듣는 서비스가 없음 → 연결 거부` | 대상의 서비스(웹 서버 80)가 꺼짐, 또는 포트 번호가 다름 | 대상 장치의 서비스 토글 켜기, 포트 확인 |
| `… 재전송 (n/3)` 반복 뒤 `TCP 실패: … ACK 없음` | 경로 어딘가에서 유실(케이블 손실률/유실 실험) 또는 경로 없음 | 케이블 손실률을 0 으로, 또는 ping 으로 먼저 경로를 확인 |
| `순서가 어긋난 데이터 … 중간 세그먼트가 유실됨` | 세그먼트 하나가 유실되어 뒤 세그먼트가 먼저 도착 | 정상 복구 과정. 서버가 타임아웃 후 재전송한다 |
| `종료된 연결로 FIN·ACK 가 다시 옴 → ACK 재전송` | 내 마지막 ACK 이 유실됨 | 정상 복구 과정 |
| `주소 변경` 으로 연결 실패 | 전송 중 IP 모드/주소를 바꿈 | 정상. 다시 연결 |

## 그 밖에

- **시계가 멈춰 있다**: 패킷이 없고 대기 이벤트도 없으면 시계는 일부러 멈춘다. 동작(ping, 케이블 연결)을 하면 다시 흐른다.
- **일시정지 상태에서 아무 일도 없다**: 상단 ▶ 재생 또는 다음 이벤트(→). Space 로 토글.
- **장치가 캔버스 밖에 있다**: 예제를 다시 불러오면 내용에 맞춰 화면을 잡는다. 휠로 이동, ⌘+휠로 확대·축소.
- **케이블이 안 이어진다** ("빈 포트가 없습니다" / "이미 연결되어 있습니다"): 포트 수 한도(호스트 1, 라우터 5, 스위치 8), 같은 두 장치 사이는 케이블 1개만.
