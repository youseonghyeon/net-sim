# 개발 중 반복된 문제와 교훈

2026-09-18 하루 동안 0 → 5단계까지 만들며 실제로 겪은 문제만 적는다. 같은 실수를 두 번 하지 않기 위한 문서다.
(사용자에게 보이는 통신 실패의 원인은 `docs/TROUBLESHOOTING.md` 에 따로 있다.)

## 1. 설계·아키텍처에서 나온 문제

| 증상 | 원인 | 고친 방법 / 교훈 |
|---|---|---|
| 첫 버전(고정 시나리오 + 재생 버튼)을 보고 "내가 바란 게 아니다" | 목적(직접 구성하고 결과를 보는 도구)을 확인하지 않고 만들었다 | 큰 UI 를 만들기 전에 **디자인 방향과 상호작용 모델을 먼저 보여주고 확인**받는다. 이후 "1단계만 만들고 디자인 체크" 로 진행해 승인받았다 |
| 라우터 LAN 을 바꿔도 호스트가 옛 서브넷 주소를 받음 | DHCP 범위가 LAN 설정과 별개 필드였고, 서버가 같은 MAC 에 옛 임대를 무조건 재사용 | **설정이 바뀌면 그 설정에서 파생된 상태(임대·ARP·연결)를 무효화**한다. 인스펙터는 LAN 변경 시 범위를 자동으로 옮기고 서브넷 밖 범위를 오류로 표시 |
| NAT 박스가 역변환한 패킷을 안쪽으로 못 보냄 | 인터페이스의 `sendIp` 가 자체 라우팅(서브넷/게이트웨이)을 다시 해서 라우팅 테이블 결정을 덮어씀 | 계층 분리: 라우터가 정한 넥스트 홉을 `sendIp(pkt, ctx, emit, nextHop)` 로 넘긴다. 그리고 실제 장비처럼 **스태틱 라우팅** 기능이 필요했다 |
| UI 에서 장치를 지우면 DHCP Release 가 안 나감 (코어 테스트는 통과) | 모델→코어 diff 동기화가 케이블을 먼저 끊고 장치를 나중에 지워서 `onRemove` 시점에 링크가 이미 down | **diff 동기화의 처리 순서가 곧 의미**다. 장치 제거를 케이블 제거보다 먼저. 그리고 `src/model/sim.ts` 는 vitest 로 안 덮이므로(브라우저 전용) Playwright 에서 반드시 확인 |
| 케이블 2개로 루프를 만들면 브라우저 탭이 죽음 | 이더넷엔 TTL 이 없고 스위치 플러딩이 지수적으로 불어남 | 시뮬레이터 전용 안전장치: 프레임 홉 수 + 스위치의 "같은 프레임 재수신" 감지(`switch.loop`), 같은 두 장치 사이 두 번째 케이블은 UI 가 거부, 프레임당 이벤트 4000 초과 시 자동 일시정지. **사용자 입력으로 무한 루프가 가능한 곳은 상한을 둔다** |
| 조용한데 시계가 1000ms, 2000ms 로 점프 | 성공한 뒤에도 ARP/ping 타이머가 큐에 남아 "아무것도 안 움직이면 다음 이벤트로 점프" 규칙에 걸림 | 타이머는 **취소 가능 핸들**로 만들고 성공 시 취소. 제거된 노드의 타이머는 큐에서 건너뜀 |
| 사용자 동작 뒤 로그 시각이 3141.66ms 처럼 소수 | 애니메이션 시계(실수)를 그대로 이벤트 시각으로 씀 | 사용자 개입 시각은 정수 ms 로 올림(`settleTime`) |
| 같은 IP 로 장치를 갈아끼우면 영원히 ping 실패 | ARP 캐시가 만료되지 않고 새 장치가 자기를 알리지 않음 | Gratuitous ARP(주소 획득·링크 업·수동 변경 시) + ARP TTL 60초. **실제 프로토콜이 이미 답을 갖고 있는 문제는 그 답을 구현**한다 |
| TCP 마지막 ACK 손실 시 한쪽이 "실패" | TIME_WAIT 이 없어 종료된 연결이 재전송된 FIN 을 무시 | 종료된 연결로 FIN/데이터가 오면 ACK 재전송. 끝난 연결과 같은 4-tuple 의 새 SYN 은 새 연결로 |
| 스위치에 "업링크" 포트를 위쪽에 따로 뒀더니 실물과 다르다는 지적 | 다이어그램 편의로 포트를 두 줄로 나눔 | 스위치는 아래쪽 포트 한 줄만. 위에 있는 장치로 가는 케이블은 짧게 나갔다가 위로 굽는다(`cableCurve` 의 lead 를 상대 방향에 따라 줄임) |

## 2. 도구·프레임워크에서 나온 문제

| 증상 | 원인 | 고친 방법 / 교훈 |
|---|---|---|
| Preact `Cycle detected` 로 앱이 시작조차 안 됨 | `effect` 안에서 `signal.value += 1` (읽고 쓰기) | effect 안에서 쓰는 signal 은 `.peek()` 로 읽는다: `v.value = v.peek() + 1` |
| 상단바 버튼이 화면 밖으로 날아감 | 팔레트 드래그 고스트 `.ghost` 와 버튼 변형 `.btn.ghost` 클래스 충돌 | 상태 클래스는 컴포넌트 접두어로 구분(`drag-ghost`). 전역 CSS 에서 짧은 단어 클래스는 피한다 |
| 캔버스 한가운데 "비어 있음" 글자가 떠 있음 (2026-09-19, **같은 실수 두 번째**) | 캔버스 빈 상태 `.empty`(position absolute, inset 0) 와 표의 빈 셀 `td.empty` 충돌 → 표 셀이 화면 전체에 깔림 | `.canvas-empty` 로 개명. **규칙: 전역 CSS 클래스는 반드시 컴포넌트 접두어**(`canvas-`, `fw-`, `pool-`…). 새 CSS 를 추가할 때 같은 이름이 이미 있는지 grep 한다 |
| 장치 드래그가 버벅임 | 위치 이동마다 시뮬레이션 동기화 + 패널 전체 재렌더 | diff 에서 **실제로 바뀐 게 없으면 bump 하지 않는다** (위치는 시뮬레이션과 무관) |
| Playwright: SVG 텍스트 `innerText` 오류 | SVG 요소는 HTMLElement 가 아님 | `textContent()` 사용 |
| Playwright: 장치 클릭이 선택을 안 함 | 라벨은 `pointer-events: none` 이라 클릭이 뒤 캔버스로 감 / 로그 서랍이 열려 아래쪽 장치가 가려짐 | 타일 중심 좌표를 계산해 `mouse.click`, 확인 전에 로그 서랍을 닫는다 |
| Playwright: `text=DHCP 임대 갱신` 이 엉뚱한 곳을 클릭 | 같은 문구가 로그·안내문에도 있음 | `button:has-text('…')` 처럼 역할을 붙인다 |
| Playwright: `input[value^='192.168.127']` 가 0개 | Preact 는 value 를 **속성이 아닌 프로퍼티**로 설정 | `evaluateAll(els => els.map(e => e.value))` 로 읽는다 |
| 검증 스크립트가 "포트 5173 사용 중" 으로 실패 | 사용자가 띄운 개발 서버와 충돌 | 검증은 별도 포트(5199)로 Vite 를 직접 띄운다. **사용자 프로세스는 건드리지 않는다** |
| Bash 도구가 명령을 거부 (control characters) | 소스나 문서에 U+0001 같은 제어 문자 리터럴, 또는 그걸 적은 문장 | 구분자로 제어 문자를 쓰지 않는다. 문서는 heredoc 대신 파일 쓰기 도구로 |
| TypeScript 7 / Vite 8 / Vitest 5 | 새 메이저지만 `tsc --noEmit`, `vitest/config` 의 `defineConfig` 로 문제 없음 | 버전을 고정하지 말고 그대로 쓴다 |

## 3. 테스트에서 나온 문제

| 증상 | 원인 | 교훈 |
|---|---|---|
| Gratuitous ARP 추가 후 ping 테스트 4개 깨짐 | 테스트가 "케이블 연결 직후" 상태를 가정하고 절대 시각 0 에서 시작 | 시나리오를 `runToIdle()` 로 **안정화한 뒤** 트레이스 인덱스를 기준으로 단언한다 |
| 루프 방어 추가 후 스위치 테스트 깨짐 | 테스트 프레임이 전부 `id: 1` | 테스트 데이터도 실제 불변식(프레임 id 유일)을 지킨다 |
| `trace.at(-1).kind === "dhcp.release"` 가 깨짐 | 다른 노드가 뒤에 트레이스를 더 남김 | 마지막 항목 대신 `some()` 이나 구간 검사 |
| 케이블 손실 시점을 잡으려다 스텝을 놓침 | 한 `step()` 안에 트레이스가 여러 개라 `at(-1)` 은 L1 항목 | 스텝 전 길이를 기록하고 `slice(before).some(...)` |

## 4. 효과가 있었던 방식

- **트레이스 시퀀스를 그대로 단언**하는 테스트(`nodeId:kind` 배열)가 프로토콜 순서 회귀를 즉시 잡았다. 요약문이 아니라 kind 로 단언한다.
- **별도 컨텍스트의 리뷰 에이전트**에게 "프로브를 직접 실행해 재현하라" 고 시키니 네 번에 걸쳐 45건의 실제 버그가 나왔다(15·9·12·9건). 큰 기능 뒤에 반드시 돌린다.
- Playwright 스모크(`npm run ui-check`)를 **기능마다 한 단계씩 늘려** 사용자 흐름 전체를 한 번에 재실행한다. 코어 테스트가 통과해도 UI 동기화 버그(제거 순서)는 여기서만 잡혔다 — 이후 동기화 로직을 `netSync.ts` 로 분리해 같은 시나리오를 vitest 로도 돌린다(CPU 가 훨씬 싸다).
- 로그 문구를 "무엇을 보고 → 어떤 결정 → 결과 + 고치는 법" 으로 쓰니 디버깅과 학습이 같은 문장으로 해결됐다.

| NAT 박스 뒤 호스트가 8.8.8.8 을 직접 DNS 로 쓰면 응답이 사라짐 (라우터는 됨) | NAT 박스의 UDP 수신 경로가 "내 주소로 온 UDP = 듣는 서비스 없음" 으로 버렸고, TCP/ICMP 만 `nat.restore` 를 탔다 | 같은 기능을 두 장치(라우터·NAT 박스)에 구현하면 **프로토콜별 분기를 둘 다 점검**한다. 3차 리뷰에서 발견 |
| DNS 서버 호스트가 자기 주소를 DNS 로 두면 자기 IP 에 ARP 를 보내다 실패 | 인터페이스 송신에 루프백이 없었다 | `NetInterface.loopback` 훅: 목적지가 내 주소면 네트워크로 나가지 않고 바로 수신 처리 |
| 서버 두 대가 서로를 업스트림 DNS 로 두면 무한 재귀 | 홉 제한이 없었다 | 질의에 `hops` 를 실어 4 초과면 SERVFAIL. **재귀·릴레이·포워딩처럼 "남에게 넘기는" 기능엔 항상 홉 상한** |
| 업스트림 DNS 무응답 시 잘못된 원인 문구("서버가 응답 없음") | 리졸버 총 대기(2×1s)가 서버의 상위 타임아웃(2s)보다 짧아 SERVFAIL 이 늦게 도착 | 계층 간 타임아웃은 **안쪽이 바깥보다 짧게**(상위 1.5s < 리졸버 2s×2). 테스트가 `reason` 까지 단언하지 않아 놓쳤다 |

| 저장했다 다시 열면 게이트웨이의 서브 인터페이스·방화벽·포워딩이 사라짐 | `normalizeTopology` 가 L3 설정을 필드 몇 개만 골라 새 객체로 만들었다 | 정규화는 **스프레드로 시작해 채워 넣기만** 한다(`{ ...saved, x: saved.x ?? default }`). 필드를 추가할 때마다 정규화를 갱신하는 건 잊기 쉬우니 보존 테스트(`tests/topology.test.ts`) 로 고정. 4차 리뷰 |
| 무선 단말이 다른 AP 로 로밍해도 시뮬레이션은 옛 AP 에 붙어 있음 | 무선 링크 id 가 `wl_<단말>` 이라 기지·슬롯이 바뀌어도 diff 가 "같은 링크" 로 봤다 | diff 의 키에는 **동일성을 결정하는 모든 값**(단말·기지·슬롯)을 넣는다. sim.ts 는 DOM 의존이라 모델 층(`wirelessLinks`)에서 id 변화를 테스트로 고정 |
| 게이트웨이 두 대가 같은 VLAN 을 쓰면 서브 인터페이스 MAC 이 충돌 | MAC 뒤 두 옥텟(장치 식별)을 포트·VLAN 으로 덮어썼다 | 파생 MAC 은 **장치 식별 옥텟을 보존**하고 다른 옥텟에 파생 정보를 넣는다(`06:<vlan>:<port>:XX:YY`). 장치 N대 조합 테스트 추가 |
| 방화벽 CIDR `10.0.0.0/` 이 prefix 0(모두 일치)로 통과 | `split("/")` 의 빈 문자열이 `Number("") === 0` | 사용자 입력 파서는 **빈 조각을 명시적으로 거부**한다. `Number("")` 은 0 이다 |

| 상단 바에 버튼을 5개 더 넣자 오른쪽 묶음이 두 줄로 내려가 캔버스 위에 겹침 | `grid-template-columns: 1fr auto 1fr` 의 `1fr` 은 최소 폭이 내용 크기라, 긴 `<select>` 옵션 문구가 열을 밀었다 | 닫힌 `<select>` 는 `width` 를 고정하고, 덜 중요한 텍스트(장치 수)는 좁은 화면에서 숨긴다. ui-check 의 "body 높이 == 캔버스 높이" 검사로는 안 잡혀서 첫 클릭이 가려진 걸로 발견 |
| 예제를 불러오면 안내 토스트가 아래쪽 장치를 덮어 ui-check 클릭이 빗나감 | 토스트가 캔버스 하단 중앙에 2.6초 떠 있고, 포인터 이벤트를 먹는다 | 스크립트는 `.toast` 가 사라질 때까지 기다린 뒤 클릭. 앱은 그대로(사용자는 기다리거나 다른 곳을 먼저 클릭) |
| 붙여넣기 오프셋 48px 이 호스트 이름 줄과 겹침 | 호스트 타일은 64 + 아래 이름·주소 줄 46 이라 세로로 110 은 비켜야 한다 | 오프셋 112. 타일 크기를 바꾸면 `PASTE_OFFSET` 도 같이 본다 |
| 입력 칸에 포커스가 있으면 ⌘D 가 안 먹음 | 단축키 핸들러가 INPUT/SELECT 를 무시하는 게 의도 | 정상. 스크립트는 `activeElement.blur()` 후 단축키 |

| 용어 정리 요청을 두 번 잘못 읽음: "쉬운 말로" 로 읽었다가, 다음엔 장치 이름까지 뒤집자고 제안 | 사용자가 나열한 "DHCP 임대 갱신, 인바운드/아웃바운드" 는 **불만이 아니라 원하는 답**(이 통용어를 써 달라)이었다 | 사용자가 예시 용어를 나열하면 그게 곧 정답 후보다. 바꿀 범위(문구만 vs 장치 이름까지)는 표로 먼저 보여 주고 확인받는다. 결과 규칙은 AGENTS.md "용어" 항목 |

## 4b. 병렬 에이전트로 만들 때 (DNS·포트 포워딩·허브)

- 공용 파일(`trace.ts` 의 kind 유니온, `packet.ts` 의 메시지 타입, `nat.ts` 의 규칙 타입)을 **먼저 넣고 커밋한 뒤** 에이전트를 띄웠다. 에이전트마다 편집 가능한 파일 목록을 명시하고 나머지는 금지. 충돌 0건.
- 에이전트가 만든 노드(`Hub`)는 `NodeType` 유니온을 못 고치니 캐스트로 두고 통합자가 유니온을 넓혔다. 이런 "통합자가 할 일" 은 에이전트 보고서에 적게 한다.
- 검증은 마지막에 한 번만 브라우저로 — 에이전트가 각자 vitest 를 반복하면 CPU 가 튄다(사용자가 발열을 지적). 에이전트 지시에 "vitest 는 필요할 때만, 헤드리스 브라우저 금지" 를 넣는다.
- 팔레트 항목이 9개가 되자 팔레트의 min-content 높이가 그리드 행을 밀어 캔버스가 푸터를 덮었다. 세로로 자라는 사이드바는 `min-height: 0; overflow-y: auto` 를 처음부터 준다. 검증 스크립트에 "body 높이 == 캔버스 높이" 레이아웃 회귀 검사를 넣었다.
- Playwright 에서 `{ hasText: "TCP 연결" }` 이 안내문("TCP 연결은 …")까지 잡아 엉뚱한 섹션을 골랐다. 섹션은 제목(`h3` 정확 일치)으로 찾는다.

## 4c. 순수 모듈을 에이전트에 맡길 때 (구성 검사·traceroute)

- 두 에이전트에게 각각 **파일 경계와 API 형태(타입·함수 시그니처)를 먼저 확정**해 주고, 메인은 그 API 만 보고 UI 통합을 동시에 진행했다. 에이전트가 끝나기 전에 통합 코드를 써도 됐고 충돌은 0건.
- 에이전트 지시에 "기존 예제 3종은 이슈 0개" 같은 **오탐 방지 기준**을 넣으니 규칙마다 침묵 조건이 붙어서 왔다. "무엇을 잡아라" 만 주면 과잉 경고가 온다.
- 에이전트 보고서의 문서 초안(TROUBLESHOOTING 행)은 메인이 붙였다. 문서 파일은 메인만 만지게 해야 병합이 없다.

## 5. 아직 남은 약점

- ~~`src/model/sim.ts` 는 DOM 의존이라 유닛 테스트가 없다~~ → 2026-09-20 에 `netSync.ts`(diff 동기화)·`simClock.ts`(시계)·`status.ts`(문구)로 분리해 유닛 테스트 26개를 붙였다. 예제 토폴로지 3종을 sync → runToIdle → ping 으로 검증하므로 브라우저 없이도 ui-check 의 핵심 흐름을 대신한다. `sim.ts` 에 남은 건 신호·rAF 접착뿐이라 테스트하지 않는다.

- 되감기(rewind)는 1차 버전에서 지원했다가 라이브 편집 도입으로 뺐다. 로그가 대신한다.
