# 개발 중 반복된 문제와 교훈

2026-09-18 하루 동안 0 → 5단계까지 만들며 실제로 겪은 문제만 적는다. 같은 실수를 두 번 하지 않기 위한 문서다.
(사용자에게 보이는 통신 실패의 원인은 `docs/TROUBLESHOOTING.md` 에 따로 있다.)

## 1. 설계·아키텍처에서 나온 문제

| 증상 | 원인 | 고친 방법 / 교훈 |
|---|---|---|
| 첫 버전(고정 시나리오 + 재생 버튼)을 보고 "내가 바란 게 아니다" | 목적(직접 구성하고 결과를 보는 도구)을 확인하지 않고 만들었다 | 큰 UI 를 만들기 전에 **디자인 방향과 상호작용 모델을 먼저 보여주고 확인**받는다. 이후 "1단계만 만들고 디자인 체크" 로 진행해 승인받았다 |
| 라우터 LAN 을 바꿔도 호스트가 옛 서브넷 주소를 받음 | DHCP 범위가 LAN 설정과 별개 필드였고, 서버가 같은 MAC 에 옛 임대를 무조건 재사용 | **설정이 바뀌면 그 설정에서 파생된 상태(임대·ARP·연결)를 무효화**한다. 인스펙터는 LAN 변경 시 범위를 자동으로 옮기고 서브넷 밖 범위를 오류로 표시 |
| NAT 박스가 역변환한 패킷을 안쪽으로 못 보냄 | 인터페이스의 `sendIp` 가 자체 라우팅(서브넷/게이트웨이)을 다시 해서 라우팅 테이블 결정을 덮어씀 | 계층 분리: 라우터가 정한 넥스트 홉을 `sendIp(pkt, ctx, emit, nextHop)` 로 넘긴다. 그리고 실제 장비처럼 **스태틱 라우팅** 기능이 필요했다 |
| UI 에서 장치를 지우면 DHCP Release 가 안 나감 (코어 테스트는 통과) | 모델→코어 diff 동기화가 케이블을 먼저 끊고 장치를 나중에 지워서 `onRemove` 시점에 링크가 이미 down | **diff 동기화의 처리 순서가 곧 의미**다. 장치 제거를 케이블 제거보다 먼저. 그리고 `src/model/sim.ts` 는 vitest 로 안 덮이므로(브라우저 전용) Playwright 에서 반드시 확인 |
| 케이블 2개로 루프를 만들면 브라우저 탭이 죽음 | 이더넷엔 TTL 이 없고 스위치 플러딩이 지수적으로 불어남 | 시뮬레이터 전용 안전장치: 프레임 홉 수 + 스위치의 "같은 프레임 재수신" 감지(`switch.loop`), 같은 두 장치 사이 두 번째 케이블은 UI 가 거부, 프레임당 이벤트 4000 초과 시 자동 일시정지. **사용자 입력으로 무한 루프가 가능한 곳은 상한을 둔다** |
| 조용한데 시계가 1000ms, 2000ms 로 점프 | 성공한 뒤에도 ARP/ping 타이머가 큐에 남아 "아무것도 안 움직이면 다음 이벤트로 점프" 규칙에 걸림 | 타이머는 **취소 가능 핸들**로 만들고 성공 시 취소. 제거된 노드의 타이머는 큐에서 건너뜀 |
| 사용자 동작 뒤 로그 시각이 3141.66ms 처럼 소수 | 애니메이션 시계(실수)를 그대로 이벤트 시각으로 씀 | 사용자 개입 시각은 정수 ms 로 올림(`settleTime`) |
| 같은 IP 로 장치를 갈아끼우면 영원히 ping 실패 | ARP 캐시가 만료되지 않고 새 장치가 자기를 알리지 않음 | Gratuitous ARP(주소 획득·링크 업·수동 변경 시) + ARP TTL 60초. **실제 프로토콜이 이미 답을 갖고 있는 문제는 그 답을 구현**한다 |
| TCP 마지막 ACK 손실 시 한쪽이 "실패" | TIME_WAIT 이 없어 종료된 연결이 재전송된 FIN 을 무시 | 종료된 연결로 FIN/데이터가 오면 ACK 재전송. 끝난 연결과 같은 4-tuple 의 새 SYN 은 새 연결로 |
| 스위치에 "업링크" 포트를 위쪽에 따로 뒀더니 실물과 다르다는 지적 | 다이어그램 편의로 포트를 두 줄로 나눔 | 스위치는 아래쪽 포트 한 줄만. 위에 있는 장치로 가는 케이블은 짧게 나갔다가 위로 굽는다(`cableCurve` 의 lead 를 상대 방향에 따라 줄임) |

## 2. 도구·프레임워크에서 나온 문제

| 증상 | 원인 | 고친 방법 / 교훈 |
|---|---|---|
| Preact `Cycle detected` 로 앱이 시작조차 안 됨 | `effect` 안에서 `signal.value += 1` (읽고 쓰기) | effect 안에서 쓰는 signal 은 `.peek()` 로 읽는다: `v.value = v.peek() + 1` |
| 상단바 버튼이 화면 밖으로 날아감 | 팔레트 드래그 고스트 `.ghost` 와 버튼 변형 `.btn.ghost` 클래스 충돌 | 상태 클래스는 컴포넌트 접두어로 구분(`drag-ghost`). 전역 CSS 에서 짧은 단어 클래스는 피한다 |
| 캔버스 한가운데 "비어 있음" 글자가 떠 있음 (2026-09-19, **같은 실수 두 번째**) | 캔버스 빈 상태 `.empty`(position absolute, inset 0) 와 표의 빈 셀 `td.empty` 충돌 → 표 셀이 화면 전체에 깔림 | `.canvas-empty` 로 개명. **규칙: 전역 CSS 클래스는 반드시 컴포넌트 접두어**(`canvas-`, `fw-`, `pool-`…). 새 CSS 를 추가할 때 같은 이름이 이미 있는지 grep 한다 |
| 장치 드래그가 버벅임 | 위치 이동마다 시뮬레이션 동기화 + 패널 전체 재렌더 | diff 에서 **실제로 바뀐 게 없으면 bump 하지 않는다** (위치는 시뮬레이션과 무관) |
| Playwright: SVG 텍스트 `innerText` 오류 | SVG 요소는 HTMLElement 가 아님 | `textContent()` 사용 |
| Playwright: 장치 클릭이 선택을 안 함 | 라벨은 `pointer-events: none` 이라 클릭이 뒤 캔버스로 감 / 로그 서랍이 열려 아래쪽 장치가 가려짐 | 타일 중심 좌표를 계산해 `mouse.click`, 확인 전에 로그 서랍을 닫는다 |
| Playwright: `text=DHCP 임대 갱신` 이 엉뚱한 곳을 클릭 | 같은 문구가 로그·안내문에도 있음 | `button:has-text('…')` 처럼 역할을 붙인다 |
| Playwright: `input[value^='192.168.127']` 가 0개 | Preact 는 value 를 **속성이 아닌 프로퍼티**로 설정 | `evaluateAll(els => els.map(e => e.value))` 로 읽는다 |
| 검증 스크립트가 "포트 5173 사용 중" 으로 실패 | 사용자가 띄운 개발 서버와 충돌 | 검증은 별도 포트(5199)로 Vite 를 직접 띄운다. **사용자 프로세스는 건드리지 않는다** |
| Bash 도구가 명령을 거부 (control characters) | 소스나 문서에 U+0001 같은 제어 문자 리터럴, 또는 그걸 적은 문장 | 구분자로 제어 문자를 쓰지 않는다. 문서는 heredoc 대신 파일 쓰기 도구로 |
| TypeScript 7 / Vite 8 / Vitest 5 | 새 메이저지만 `tsc --noEmit`, `vitest/config` 의 `defineConfig` 로 문제 없음 | 버전을 고정하지 말고 그대로 쓴다 |

## 3. 테스트에서 나온 문제

| 증상 | 원인 | 교훈 |
|---|---|---|
| Gratuitous ARP 추가 후 ping 테스트 4개 깨짐 | 테스트가 "케이블 연결 직후" 상태를 가정하고 절대 시각 0 에서 시작 | 시나리오를 `runToIdle()` 로 **안정화한 뒤** 트레이스 인덱스를 기준으로 단언한다 |
| 루프 방어 추가 후 스위치 테스트 깨짐 | 테스트 프레임이 전부 `id: 1` | 테스트 데이터도 실제 불변식(프레임 id 유일)을 지킨다 |
| `trace.at(-1).kind === "dhcp.release"` 가 깨짐 | 다른 노드가 뒤에 트레이스를 더 남김 | 마지막 항목 대신 `some()` 이나 구간 검사 |
| 케이블 손실 시점을 잡으려다 스텝을 놓침 | 한 `step()` 안에 트레이스가 여러 개라 `at(-1)` 은 L1 항목 | 스텝 전 길이를 기록하고 `slice(before).some(...)` |

## 4. 효과가 있었던 방식

- **트레이스 시퀀스를 그대로 단언**하는 테스트(`nodeId:kind` 배열)가 프로토콜 순서 회귀를 즉시 잡았다. 요약문이 아니라 kind 로 단언한다.
- **별도 컨텍스트의 리뷰 에이전트**에게 "프로브를 직접 실행해 재현하라" 고 시키니 다섯 번에 걸쳐 60건 넘는 실제 버그가 나왔다(15·9·12·9건, 5차는 코어·모델·UI·문서 4개 병렬로 약 20건). 큰 기능 뒤에 반드시 돌린다.
- Playwright 스모크(`npm run ui-check`)를 **기능마다 한 단계씩 늘려** 사용자 흐름 전체를 한 번에 재실행한다. 코어 테스트가 통과해도 UI 동기화 버그(제거 순서)는 여기서만 잡혔다 — 이후 동기화 로직을 `netSync.ts` 로 분리해 같은 시나리오를 vitest 로도 돌린다(CPU 가 훨씬 싸다).
- 로그 문구를 "무엇을 보고 → 어떤 결정 → 결과 + 고치는 법" 으로 쓰니 디버깅과 학습이 같은 문장으로 해결됐다.

| NAT 박스 뒤 호스트가 8.8.8.8 을 직접 DNS 로 쓰면 응답이 사라짐 (라우터는 됨) | NAT 박스의 UDP 수신 경로가 "내 주소로 온 UDP = 듣는 서비스 없음" 으로 버렸고, TCP/ICMP 만 `nat.restore` 를 탔다 | 같은 기능을 두 장치(라우터·NAT 박스)에 구현하면 **프로토콜별 분기를 둘 다 점검**한다. 3차 리뷰에서 발견 |
| DNS 서버 호스트가 자기 주소를 DNS 로 두면 자기 IP 에 ARP 를 보내다 실패 | 인터페이스 송신에 루프백이 없었다 | `NetInterface.loopback` 훅: 목적지가 내 주소면 네트워크로 나가지 않고 바로 수신 처리 |
| 서버 두 대가 서로를 업스트림 DNS 로 두면 무한 재귀 | 홉 제한이 없었다 | 질의에 `hops` 를 실어 4 초과면 SERVFAIL. **재귀·릴레이·포워딩처럼 "남에게 넘기는" 기능엔 항상 홉 상한** |
| 업스트림 DNS 무응답 시 잘못된 원인 문구("서버가 응답 없음") | 리졸버 총 대기(2×1s)가 서버의 업스트림 질의 타임아웃(2s)보다 짧아 SERVFAIL 이 늦게 도착 | 계층 간 타임아웃은 **안쪽이 바깥보다 짧게**(업스트림 1.5s < 리졸버 2s×2). 테스트가 `reason` 까지 단언하지 않아 놓쳤다 |

| 저장했다 다시 열면 게이트웨이의 서브 인터페이스·방화벽·포워딩이 사라짐 | `normalizeTopology` 가 L3 설정을 필드 몇 개만 골라 새 객체로 만들었다 | 정규화는 **스프레드로 시작해 채워 넣기만** 한다(`{ ...saved, x: saved.x ?? default }`). 필드를 추가할 때마다 정규화를 갱신하는 건 잊기 쉬우니 보존 테스트(`tests/topology.test.ts`) 로 고정. 4차 리뷰 |
| 무선 단말이 다른 AP 로 로밍해도 시뮬레이션은 옛 AP 에 붙어 있음 | 무선 링크 id 가 `wl_<단말>` 이라 기지·슬롯이 바뀌어도 diff 가 "같은 링크" 로 봤다 | diff 의 키에는 **동일성을 결정하는 모든 값**(단말·기지·슬롯)을 넣는다. sim.ts 는 DOM 의존이라 모델 층(`wirelessLinks`)에서 id 변화를 테스트로 고정 |
| 게이트웨이 두 대가 같은 VLAN 을 쓰면 서브 인터페이스 MAC 이 충돌 | MAC 뒤 두 옥텟(장치 식별)을 포트·VLAN 으로 덮어썼다 | 파생 MAC 은 **장치 식별 옥텟을 보존**하고 다른 옥텟에 파생 정보를 넣는다(`06:<vlan>:<port>:XX:YY`). 장치 N대 조합 테스트 추가 |
| 방화벽 CIDR `10.0.0.0/` 이 prefix 0(모두 일치)로 통과 | `split("/")` 의 빈 문자열이 `Number("") === 0` | 사용자 입력 파서는 **빈 조각을 명시적으로 거부**한다. `Number("")` 은 0 이다 |

| 상단 바에 버튼을 5개 더 넣자 오른쪽 묶음이 두 줄로 내려가 캔버스 위에 겹침 | `grid-template-columns: 1fr auto 1fr` 의 `1fr` 은 최소 폭이 내용 크기라, 긴 `<select>` 옵션 문구가 열을 밀었다 | 닫힌 `<select>` 는 `width` 를 고정하고, 덜 중요한 텍스트(장치 수)는 좁은 화면에서 숨긴다. ui-check 의 "body 높이 == 캔버스 높이" 검사로는 안 잡혀서 첫 클릭이 가려진 걸로 발견 |
| 예제를 불러오면 안내 토스트가 아래쪽 장치를 덮어 ui-check 클릭이 빗나감 | 토스트가 캔버스 하단 중앙에 2.6초 떠 있고, 포인터 이벤트를 먹는다 | 스크립트는 `.toast` 가 사라질 때까지 기다린 뒤 클릭. 앱은 그대로(사용자는 기다리거나 다른 곳을 먼저 클릭) |
| 붙여넣기 오프셋 48px 이 호스트 이름 줄과 겹침 | 호스트 타일은 64 + 아래 이름·주소 줄 46 이라 세로로 110 은 비켜야 한다 | 오프셋 112. 타일 크기를 바꾸면 `PASTE_OFFSET` 도 같이 본다 |
| 입력 칸에 포커스가 있으면 ⌘D 가 안 먹음 | 단축키 핸들러가 INPUT/SELECT 를 무시하는 게 의도 | 정상. 스크립트는 `activeElement.blur()` 후 단축키 |

| 용어 정리 요청을 두 번 잘못 읽음: "쉬운 말로" 로 읽었다가, 다음엔 장치 이름까지 뒤집자고 제안 | 사용자가 나열한 "DHCP 임대 갱신, 인바운드/아웃바운드" 는 **불만이 아니라 원하는 답**(이 통용어를 써 달라)이었다 | 사용자가 예시 용어를 나열하면 그게 곧 정답 후보다. 바꿀 범위(문구만 vs 장치 이름까지)는 표로 먼저 보여 주고 확인받는다. 결과 규칙은 AGENTS.md "용어" 항목 |

| 장치를 지우거나 붙여 넣으면 영역이 전부 사라짐 | `setTopology({ devices, cables })` 로 새 객체를 만들며 선택 필드 `zones` 를 빠뜨림. 선택 필드라 tsc 도 못 잡음 | 토폴로지를 바꾸는 코드는 **항상 `{ ...t, … }` 로 시작**한다. 새 최상위 필드를 추가하면 `setTopology(` 호출부를 전부 grep. 5차 리뷰 |

## 4b. 병렬 에이전트로 만들 때 (DNS·포트 포워딩·허브)

- 공용 파일(`trace.ts` 의 kind 유니온, `packet.ts` 의 메시지 타입, `nat.ts` 의 규칙 타입)을 **먼저 넣고 커밋한 뒤** 에이전트를 띄웠다. 에이전트마다 편집 가능한 파일 목록을 명시하고 나머지는 금지. 충돌 0건.
- 에이전트가 만든 노드(`Hub`)는 `NodeType` 유니온을 못 고치니 캐스트로 두고 통합자가 유니온을 넓혔다. 이런 "통합자가 할 일" 은 에이전트 보고서에 적게 한다.
- 검증은 마지막에 한 번만 브라우저로 — 에이전트가 각자 vitest 를 반복하면 CPU 가 튄다(사용자가 발열을 지적). 에이전트 지시에 "vitest 는 필요할 때만, 헤드리스 브라우저 금지" 를 넣는다.
- 팔레트 항목이 9개가 되자 팔레트의 min-content 높이가 그리드 행을 밀어 캔버스가 푸터를 덮었다. 세로로 자라는 사이드바는 `min-height: 0; overflow-y: auto` 를 처음부터 준다. 검증 스크립트에 "body 높이 == 캔버스 높이" 레이아웃 회귀 검사를 넣었다.
- Playwright 에서 `{ hasText: "TCP 연결" }` 이 안내문("TCP 연결은 …")까지 잡아 엉뚱한 섹션을 골랐다. 섹션은 제목(`h3` 정확 일치)으로 찾는다.

## 4c. 순수 모듈을 에이전트에 맡길 때 (구성 검사·traceroute)

- 두 에이전트에게 각각 **파일 경계와 API 형태(타입·함수 시그니처)를 먼저 확정**해 주고, 메인은 그 API 만 보고 UI 통합을 동시에 진행했다. 에이전트가 끝나기 전에 통합 코드를 써도 됐고 충돌은 0건.
- 에이전트 지시에 "기존 예제 3종은 이슈 0개" 같은 **오탐 방지 기준**을 넣으니 규칙마다 침묵 조건이 붙어서 왔다. "무엇을 잡아라" 만 주면 과잉 경고가 온다.
- 에이전트 보고서의 문서 초안(TROUBLESHOOTING 행)은 메인이 붙였다. 문서 파일은 메인만 만지게 해야 병합이 없다.

## 4d. 터널(캡슐화)을 넣을 때 기존 경로가 하던 일을 다시 점검 (VPN 리뷰, 2026-09-29)

- "나에게 온 VPN 패킷이면 푼다" 를 **VPN 을 켰는지 보지 않고** 걸었더니, VPN 게이트웨이 앞의 NAT 박스가 포워딩해야 할 UDP 51820 을 가로채 드롭했다. 새 분기를 앞에 끼울 때는 그 분기를 탈 자격(기능 켜짐)을 조건에 넣는다.
- ICMP 통지를 만드는 곳이 둘(`forward` 의 `noticeFrom`, ARP 실패의 `hostUnreachable`)이었는데 한 곳만 터널을 알았다. 같은 종류의 출력을 만드는 곳을 grep 해 전부 고친다.
- 새 경로 종류(kind "vpn")를 방화벽에 "안쪽끼리" 로 넣자 in/out 규칙이 한 번도 안 맞았다. 사용자가 실제로 쓰는 규칙(기본 차단 + 아웃바운드 허용)으로 테스트를 쓰면 바로 드러난다.
- 설정 필드를 추가하면 `normalizeTopology` 에도 넣는다 — 깨진 JSON 에서 구성 검사가 예외로 멈췄다.

## 4e. 투명 히트 영역이 색 규칙에 덮임 (2026-09-29)

- 패킷을 누르기 쉽게 `<circle class="packet-hit" r=13>` 을 넣었는데, 종류별 색 규칙 `.packet.arp circle`(클래스 2 + 요소 1)이 `.packet .packet-hit`(클래스 2)보다 우선순위가 높아 칠해졌다 → 모든 패킷이 두 배 가까이 커 보였다. 사용자가 발견.
- 같은 요소 종류(circle)를 역할이 다르게 두 개 쓰면, 넓은 선택자(`… circle`)는 `:not(.역할)` 로 좁힌다. 스크린샷을 찍어도 "패킷이 원래 이 크기" 처럼 보여 놓쳤다 — ui-check 가 히트 원의 계산된 fill 이 투명인지 단언한다.

## 4f. 상태를 가진 프로토콜은 "한쪽만 초기화" 를 먼저 시험한다 (IPsec 리뷰, 2026-09-29)

- IPsec 터널 상태(SA)를 양쪽이 따로 들고 있는데, 한쪽만 설정이 바뀌어 초기화되자 다른 쪽이 끝없이 옛 SA 로 ESP 를 보냈다(재협상 계기 없음). 정상 경로·양쪽 동시 초기화만 테스트해서 놓쳤다. 상태를 가진 새 기능은 "한쪽만 리셋·주소 변경·패킷 1개 손실" 세 가지를 기본 테스트로 넣는다.
- 협상 timer 를 spi 하나로만 구분하면 앞 단계 timer 가 뒤 단계를 끊는다 → timer data 에 단계·시도 횟수까지 싣는다.

## 4g. 주기 타이머 없는 프로토콜은 "누가 언제 다시 말하나" 를 경우마다 따진다 (HA 리뷰, 2026-09-29)

- 주기 광고 없이 트리거로만 동작하게 만들었더니, 망이 갈라졌다 다시 붙는 경우처럼 **어느 쪽 장비도 상태가 안 바뀌는 사건**에는 아무도 말하지 않아 dual master 가 남았다 → 토폴로지 변화(케이블 연결)를 동기화 층에서 알려 준다(`poke`). RIP·HA 같은 트리거 방식을 새로 넣으면 "링크·주소·설정·이웃 합류·갈라짐 복구" 각각에서 누가 먼저 말하는지 표로 적어 본다.
- 동점 판정을 "받은 인터페이스의 내 주소" 로 했더니 인터페이스마다 결론이 달라 광고가 끝없이 오갔다(이벤트 20만 개). 장비 단위 판정은 장비 단위 식별자로.
- 같은 틱에 여러 케이블이 빠지면, 첫 링크 다운에 반응해 보낸 알림이 다음 케이블 제거로 지워졌다 — 장치 제거에만 있던 graceful 전달을 링크 다운 반응에도.

## 4h. "상태를 먼저 바꾸고 보낸다" 를 두 번째로 어김 (SSH 리뷰, 2026-09-29)

- 로드밸런서 때 배운 규칙(루프백은 transmit 안에서 상대 응답까지 동기로 돌아온다 → 상태를 먼저 갱신)을 SSH 단계 카운터에서 다시 어겼다(step++ 를 transmit 뒤에). 같은 실수 두 번 → 영구 가드: 새 앱 흐름을 TcpStack 에 넣으면 **자기 주소로 접속하는 루프백 테스트**를 반드시 하나 둔다(`tests/ssh.test.ts` 루프백 케이스).
- 이중화 전체 복사를 "master 가 낮은 후보를 들었을 때" 에만 넣고 "높은 후보에게 넘길 때" 를 빠뜨렸다. 상태를 넘기는 코드는 넘겨받는 쪽이 생기는 모든 경로(합류·preempt·장애)를 표로 확인한다.

## 4i. 표준의 "왜" 를 빼고 옮기면 그 이유가 버그로 돌아온다 (STP 리뷰, 2026-09-29)

- 802.1D 의 "더 좋은 정보거나 같은 보낸이의 갱신일 때만 바꾼다" 를 "받으면 덮어쓴다" 로 줄였더니, 허브에 스위치 셋이 물린 구간에서 BPDU 가 끝없이 돌았다. Topology Change 전파를 빼니 다른 스위치의 MAC 테이블이 옛 포트를 가리켜 트래픽이 사라졌다. 표준 절차를 줄일 때는 그 규칙이 막던 경우(공유 세그먼트·다른 스위치의 학습 정보)를 테스트로 먼저 만든다.
- 주기 타이머를 빼는 대신 "바뀔 때 모든 포트로" 를 넣었더니 그물에서 로그가 수만 줄 — 트리거 방식에는 같은 순간 모아 보내기(0ms 타이머)를 기본으로 둔다(RIP 의 kick 과 같은 이유).

## 4j. 동작을 바꾸지 않는 정리는 "전체 트레이스 골든" 으로 검증 (리팩터링, 2026-09-29)

- 시뮬레이터가 결정론적이므로, 정리 전에 예제 전부 + 시나리오(VPN·원격 접속·이중화)의 트레이스 전체(시각·장치·종류·문구, 3만 줄)를 저장해 두고 단계마다 비교했다. 테스트 393개가 못 보는 문구·순서 변화까지 잡힌다.
- 장치 id 는 예제를 만들 때마다 새로 생기고, ICMP id 등이 그 해시에서 나오므로 비교 전에 id 를 순서대로 고정해야 한다(안 그러면 같은 코드도 12개 시나리오가 달라 보인다). 먼저 "같은 코드 두 번" 이 같게 나오는지부터 확인한다.
- 파일 경계가 겹치지 않는 정리(구성 검사·예제·테스트 도우미)는 에이전트 3개가 각자 worktree 에서, 겹치는 것(IKE·패킷 판별·l3 분리)은 메인이 순서대로 — 합칠 때 충돌 0건.

## 4k. 루프백 가드가 LESSONS 에만 있어 세 번째로 어김 (프록시 리뷰, 2026-09-29)
- 4h 에서 "새 앱 흐름을 TcpStack 에 넣으면 루프백 테스트를 반드시 하나" 로 정했지만, 포워드 프록시를 만들 때 그 테스트를 넣지 않았다. 리뷰가 찾았다: 프록시가 자기 웹 서버를 대상으로 하면 `onRequest` 안에서 응답·FIN 까지 끝났는데, 돌아와서 `deferred` 를 세우고 "받아 오는 대로" ACK 를 FIN 뒤에 또 보냈다(LB 도 같은 코드였다).
- 원인: 규칙이 LESSONS 에만 있어 작업 중에 보이지 않았다. 매 세션 읽히는 `AGENTS.md` 의 TCP 문단으로 옮겼다(점검 항목). 고친 방식은 같다 — 앱 고리를 부르기 **전에** 상태를 세우고, 돌아온 뒤에는 상태를 **다시 확인하고** 보낸다.
- 같은 리뷰의 교훈: "응답을 기다리는 쪽에 끝을 둔다"(LB 리뷰)를 첫 바이트까지만 적용해, 응답이 중간에 멈추면 중계 연결이 영원히 열려 있었다. 기다림의 끝은 "마지막으로 받은 뒤" 로 잰다.

## 4l. 이중화 전환은 "넘겨주는 쪽이 비울 상태" 까지, 손실 테스트는 응답 쪽도 (원격 접속 EAP·DPD 리뷰, 2026-09-30)
- 세션 동기화가 복사하지 않는 상태(IPsec SA·원격 접속 세션)를 물러난 옛 master 가 그대로 들고 있었다 → 옛 master 의 DPD 에 상대가 "살아 있음" 으로 답했고, 같은 가상 주소로 협상한 두 장비의 SPI 가 겹쳤다. 4h 의 "넘겨받는 쪽 경로 표" 에 "넘겨주는 쪽이 비울 상태" 를 더한다: 상태를 가진 기능을 새로 넣으면 `HaHost.onResign` 에서 무엇을 비우는지 정하고, 이중화 쌍 + preempt 테스트를 하나 둔다.
- 4f 의 "패킷 1개 손실" 을 요청 쪽만 시험했다. 응답자의 마지막 응답이 사라지면 서버엔 유령 세션, 클라이언트엔 엉뚱한 실패 원인이 남았다 → 손실 테스트는 교환의 방향마다 마지막 메시지를 하나씩 잃게 한다(`dropNextOn` + `step()`).
- 결정론 해시로 난수를 흉내 낼 때(SPI) 씨앗에 장비마다 다른 값이 들어가는지 본다 — 가상 주소처럼 장비끼리 공유하는 값만으로는 겹친다.

## 4m. 새 계층을 옆에 붙일 때 옛 계층의 "숨은 짝" 을 표로 옮긴다 (IPv6 1단계 리뷰, 2026-09-30)
- IPv4 주소가 바뀌면 TCP 는 IPv4 연결만 끊게 걸러 놓고 traceroute 는 그대로 둬, IPv4 만 바꿔도 IPv6 traceroute 가 끊겼다. 두 버전이 한 장치에 있을 때 "주소가 바뀌면 정리하는 것" 을 목록으로 만들고(연결·traceroute·ping·캐시) 각각에 버전 필터를 단다.
- IPv4 에는 있는데 옮기지 않은 동작이 버그로 돌아왔다: 주소를 쓰기 시작할 때 알리기(Gratuitous ARP ↔ 요청하지 않은 NA), 링크 다운 시 실패 문구. 옛 계층의 "주소를 얻을 때·잃을 때·링크가 바뀔 때" 동작을 표로 적고 새 계층의 짝을 채운다.
- 입력 칸 검증은 모델 정리(`effective*`)에서 한다: `type="number"` 칸에는 64.5 가 들어오고, 그 값이 구성 검사 computed 까지 가서 예외를 던지면 화면 전체가 죽는다. 프리픽스·포트 같은 정수는 `Number.isInteger` 까지 본다(호스트는 했고 게이트웨이는 빠졌다 — 같은 칸이 두 곳이면 둘 다).
- 서로 동시에 NS 를 보낼 때 NA 하나를 잃으면 대기열이 남아 이후 NS 가 막혔다(IPv4 ARP 에도 같은 기존 결함 — 2026-09-30 에 고침: 상대의 ARP 요청으로 배워도 대기열을 보내고, 요청 timeout 때 이미 배운 주소면 대기열만 치운다, `tests/arp-queue.test.ts`). 배우는 경로가 여럿(NA·NS·RA)이면 어느 경로로 배우든 대기열을 비운다.

## 4n. `git add -A` 가 에이전트 worktree 를 gitlink 로 담는다 (2026-09-30)
- 리뷰 에이전트를 `isolation: worktree` 로 돌리면 `.claude/worktrees/<id>` 에 저장소가 생기고, 끝난 뒤 변경이 있으면 남는다. 그 상태로 `git add -A` 하면 임베디드 저장소(160000 gitlink)로 커밋·push 된다. `.gitignore` 에 `.claude/worktrees/` 를 넣어 막았고, 필요한 것(재현 테스트)을 옮긴 뒤 `git worktree remove` 로 치운다.

## 4o. 콜백이 들고 있던 ctx 의 "지금" 은 과거다 (IPv6 4단계 리뷰, 2026-09-30)
- `NodeContext.now` 가 ctx 를 만든 순간의 값이었고 `timer` 도 그 값 + delay 로 걸렸다. DNS 응답을 기다린 콜백이 사용자 동작 때의 ctx 로 TCP SYN 을 보내면 재전송 타이머가 과거에 걸려 "100ms 만에 400ms timeout" 이 찍히고, 시계가 거꾸로 갔다. IPv4 만으로도 DNS 재시도가 끼면 났지만 드물었고, AAAA → A 두 번 조회가 조건을 넓혀 드러났다. `now` 를 getter 로, `timer` 를 부르는 순간 기준으로 고쳤다(기존 테스트 트레이스는 하나도 안 바뀜 — 결함이 있던 경로만 영향).
- 교훈: 비동기로 이어지는 흐름(DNS → 연결)을 새로 여러 단계로 늘리면, 앞 단계의 문맥 객체를 뒤 단계가 쓰는지 본다.

## 4p. 한 키를 막으려던 가드가 모든 키를 막았다 (2026-09-30)
- 토글 스위치(role="switch")에서 Space 가 재생까지 바꾸지 않게 앱 단축키 처리에서 토글 포커스를 통째로 빼 두어, 토글을 누른 직후 ⌘Z·⌘C 가 먹지 않았다. ui-check 는 토글을 다시 눌러 우회하고 있었다 — 테스트에서 우회한 동작은 그 자리에서 결함으로 적는다. 포커스 예외는 그 요소가 실제로 처리하는 키(수정자 없는 키)만 뺀다.

## 4q. 준비 단계를 새로 끼우면 "받은 바이트 = 응답" 같은 옛 가정이 깨진다 (HTTPS 리뷰, 2026-09-30)
- TLS 핸드셰이크·CONNECT 응답을 넣자 옛 코드의 가정 셋이 한꺼번에 틀렸다: "서버가 아직 응답하지 않았다 = 보낸 바이트 0"(TLS 는 ServerHello 를 먼저 보냄 → L7 LB 가 받은 요청을 ACK 하지 않음), "받은 바이트 = 응답 본문"(LB 가 ServerHello 1400B 를 응답으로 부풀림), "원격 포트 443 = TLS"(443 에서 듣는 프록시로 가는 평문 요청까지 ClientHello 로 바꿈). 새 단계를 끼울 때 옛 조건식(`bytesSent === 0`, `bytesReceived`, 포트 비교)을 grep 해 전부 목록으로 만든다 — 한 곳을 고치고 같은 조건의 다른 곳(onRequest 뒤 ACK)을 놓쳤다.
- 중계는 필드를 골라 복사하지 말고 전부 넘긴다(골라 복사하다 Cookie·X-Served-By 를 잃음). "통과시키는 장치" 는 모르는 필드도 그대로가 기본이다.
- 반대 방향 짝: "평문 → TLS 포트" 를 막았으면 "TLS → 평문 포트" 도 본다.

## 4r. 설정 변경 = 재시작이 기본이면, 켜기만 해도 장애가 난다 (시계 구조 1단계, 2026-09-30)
- 이중화 `setConfig` 는 어떤 칸이 바뀌어도 선출을 다시 해, 주기 광고를 켜는 순간 master 가 물러나 넘어갔다. ui-check 는 "+10초 뒤 B 가 master" 만 봐서 통과했지만, 누르기 전에 이미 B 가 master 였다. 결과만이 아니라 전제 상태("누르기 전에는 backup")를 함께 단언한다.
- 전환 검증은 제어 상태(master/backup)만 보지 말고 데이터 경로까지 본다: 둘 다 master 였다가 정리될 때 이긴 쪽이 가상 MAC 을 다시 알리지 않아 스위치가 물러난 쪽 포트로 보내 LAN 이 끊겼다(리뷰). 실제 VRRP 가 광고의 출발지 MAC 을 가상 MAC 으로 두는 이유가 이것 — 표준의 "왜" 를 옮긴다(4i 와 같은 뿌리).
- 새로 넣은 구성 검사 문구가 타일 툴팁(<title>)에 다른 장치 이름을 넣어, `hasText` 로 장치를 찾던 ui-check 가 두 타일을 잡았다 → 장치는 이름 칸(`text.name`)이 정확히 같은 것으로 찾는다. 곡선 케이블은 상자 가운데가 선 위가 아니다 → 경로 중간 점(`getPointAtLength`)을 누른다.

## 4s. 배경 타이머의 원칙은 "상대가 반응으로 거는 타이머" 까지 (주기 동작 리뷰, 2026-10-01)
- 헬스 체크는 배경 타이머이고 체크 연결의 SYN 도 재전송하지 않게 했지만, 돌아오는 길만 끊긴 백엔드는 SYN 을 받을 때마다 SYN·ACK 재전송(일반 타이머, 5초 남짓)을 걸었다 — 2초마다 새 체크가 오니 끝없이 겹쳐 시계가 멈추지 않았다. 주기 동작을 넣을 때는 "그 동작이 상대 장비에게 일으키는 일반 타이머 사슬" 의 길이를 주기와 비교한다(주기보다 길면 겹친다).
- 주기적으로 연결을 여는 기능은 "그 연결이 남기는 상태" 를 따라가 본다: 진단 목록·자동완성의 "마지막 연결", 임시 포트 고갈·겹침, NAT 매핑 누적이 모두 처음 생긴 문제였다(사람이 누를 때는 드러나지 않던 규모).

## 5. 아직 남은 약점

- ~~`src/model/sim.ts` 는 DOM 의존이라 유닛 테스트가 없다~~ → 2026-09-20 에 `netSync.ts`(diff 동기화)·`simClock.ts`(시계)·`status.ts`(문구)로 분리해 유닛 테스트 26개를 붙였다. 예제 토폴로지 3종을 sync → runToIdle → ping 으로 검증하므로 브라우저 없이도 ui-check 의 핵심 흐름을 대신한다. `sim.ts` 에 남은 건 신호·rAF 접착뿐이라 테스트하지 않는다.
- `store.ts` 는 여전히 localStorage·matchMedia 에 모듈 로드 시점에 의존한다. 순수 검증(`planCable`)은 `topology.ts` 로 빼서 테스트한다. 편집 동작(add/move/remove)은 한 줄짜리 signal 갱신이라 테스트 가치가 낮다.

- 되감기(rewind)는 1차 버전에서 지원했다가 라이브 편집 도입으로 뺐다. 로그가 대신한다.
