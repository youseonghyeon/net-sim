# net-sim

서브넷 · ARP · DHCP · 게이트웨이 · NAT · TCP 가 **어느 지점에서 무엇을 보고 어떤 결정을 하는지** 눈으로 보기 위한 네트워크 시뮬레이터입니다. Packet Tracer 처럼 장치를 놓고 케이블을 연결해 직접 구성합니다.

```
npm install
npm run dev      # http://localhost:5173
npm test         # 코어 테스트
npm run ui-check # 브라우저 스모크 테스트 (.shots/ 에 스크린샷)
```

## 사용법
- 왼쪽 팔레트에서 PC·노트북·서버·스위치·라우터·게이트웨이·NAT·인터넷을 캔버스로 끌어다 놓습니다. 클릭하면 화면 중앙에 추가됩니다.
- **라우터(공유기)** 는 스위치 + DHCP 서버 + 게이트웨이 + NAT 가 한 몸입니다. 같은 것을 **기능 단위**로도 만들 수 있습니다: 스위치 + DHCP 서버(서버 장치의 서비스 토글) + 게이트웨이(순수 라우팅, 정적 경로) + NAT 박스(inside/outside). 상단 "예제 불러오기" 에 두 구성이 모두 있습니다.
- 케이블 도구(C)로 장치에서 장치로 끌면 상대를 향한 빈 포트끼리 연결됩니다. Shift + 드래그도 같습니다.
- 시뮬레이션은 항상 살아 있습니다. 케이블을 꽂는 순간 호스트가 DHCP 를 시도하고, 패킷이 케이블 위를 지나가는 것이 보입니다. 조용할 때는 시계가 멈춥니다.
- 장치를 선택하면 오른쪽에 현재 상태(IP, DHCP 상태, ARP/MAC/NAT/TCP 테이블), IP 설정(자동/수동), 웹 서버 토글, ping 과 TCP 연결이 나옵니다. 라우터는 LAN 주소·DHCP 서비스 토글·WAN 설정이 있습니다.
- 케이블을 선택하면 손실률을 걸거나 다음 패킷 1개를 유실시켜 TCP 재전송을 볼 수 있습니다.
- 상단 가운데에서 일시정지(Space)·다음 이벤트(→)·속도를 조절하고, 아래 이벤트 로그에서 각 장치가 무엇을 보고 어떤 결정을 했는지 계층별로 봅니다.
- 휠로 이동, ⌘ + 휠로 확대·축소. Delete 로 선택 삭제. 작업은 브라우저에 자동 저장됩니다.

## 문제가 생기면
`docs/TROUBLESHOOTING.md` 에 로그 문구별 원인과 고치는 법이 있습니다. 개발 기록은 `docs/LESSONS.md`.

## 단계
1. ✅ 디자인 시스템 + 캔버스 에디터
2. ✅ DHCP 시뮬레이션 (라우터 토글, 자동/수동 IP), ping, 패킷 애니메이션, 이벤트 로그
3. ✅ 인터넷 노드, 라우터 WAN(ISP DHCP), NAT
4. ✅ TCP: 3-way handshake, 시퀀스/ACK, 데이터 3세그먼트, FIN 종료, RST 거부, 유실 시 재전송, NAT 포트 변환
5. ✅ 기능 단위 장치: 게이트웨이(다중 서브넷 라우팅 + 정적 경로), NAT 박스, 호스트 DHCP 서버 서비스
6. 후보: DNS, 되감기, 인터넷 노드를 실제 네트워크에 연결(로컬 도우미 프로세스로 실제 ping/DNS/HTTP)
