# net-sim

서브넷 · ARP · DHCP · 게이트웨이 · NAT · TCP 가 **어느 지점에서 무엇을 보고 어떤 결정을 하는지** 눈으로 보기 위한 네트워크 시뮬레이터입니다. Packet Tracer 처럼 장치를 놓고 케이블을 연결해 직접 구성합니다.

```
npm install
npm run dev      # http://localhost:5173
npm test         # 코어 테스트
npm run ui-check # 브라우저 스모크 테스트 (.shots/ 에 스크린샷)
```

## 사용법
- 왼쪽 팔레트에서 PC·노트북·스마트폰·서버·허브·스위치·무선 AP·라우터·게이트웨이·NAT·인터넷을 캔버스로 끌어다 놓습니다. 클릭하면 화면 중앙에 추가됩니다.
- 스위치를 선택하면 포트마다 VLAN 번호(액세스) 또는 트렁크를 정할 수 있습니다. 포트 색이 VLAN 을 나타내고, VLAN 사이는 게이트웨이의 "VLAN 서브 인터페이스" 로 잇습니다. 예제 "VLAN 으로 나눈 사무실" 참고.
- 스마트폰은 케이블 대신 SSID 로 붙습니다. 무선 AP(또는 무선을 켠 공유기)의 전파 범위(점선 원) 안으로 끌어오면 자동으로 연결되고 DHCP 가 시작됩니다.
- **라우터(공유기)** 는 스위치 + DHCP 서버 + 게이트웨이 + NAT 가 한 몸입니다. 같은 것을 **기능 단위**로도 만들 수 있습니다: 스위치 + DHCP 서버(서버 장치의 서비스 토글) + 게이트웨이(순수 라우팅, 스태틱 라우팅) + NAT 박스(inside/outside). 상단 "예제 불러오기" 에 두 구성이 모두 있습니다.
- 케이블 도구(C)로 장치에서 장치로 끌면 상대를 향한 빈 포트끼리 연결됩니다. Shift + 드래그도 같습니다.
- 시뮬레이션은 항상 살아 있습니다. 케이블을 꽂는 순간 호스트가 DHCP 를 시도하고, 패킷이 케이블 위를 지나가는 것이 보입니다. 조용할 때는 시계가 멈춥니다.
- 장치를 선택하면 오른쪽에 현재 상태(IP, DHCP 상태, ARP/MAC/NAT/TCP/DNS 테이블), IP 설정(자동/수동), 서비스 토글(웹 서버·DHCP 서버·DNS 서버), ping 과 TCP 연결이 나옵니다. ping·연결 대상에 이름(google.com, web.home)을 쓸 수 있습니다.
- 라우터는 LAN 주소·DHCP·DNS 포워더·WAN·포트 포워딩·방화벽 설정이 있고, 인터넷 노드의 "외부에서 접속" 으로 바깥에서 들어오는 연결을 실험합니다. 방화벽은 게이트웨이·NAT 박스에도 있습니다(지나가는 패킷을 규칙으로 거르고, Stateful 검사으로 응답은 통과).
- 케이블을 선택하면 손실률을 걸거나 다음 패킷 1개를 손실시켜 TCP 재전송을 볼 수 있습니다.
- 상단 가운데에서 일시정지(Space)·다음 이벤트(→)·속도를 조절하고, 아래 이벤트 로그에서 각 장치가 무엇을 보고 어떤 결정을 했는지 계층별로 봅니다.
- 빈 곳을 끌면 영역 선택, Shift+클릭으로 선택에 더하거나 뺍니다. 여러 장치를 고르면 함께 옮기고, 오른쪽 패널에서 정렬·공통 설정(게이트웨이/DNS/IP 모드/SSID)·일괄 ping·DHCP 갱신을 한 번에 합니다. ⌘C/⌘V/⌘D 로 복제(묶음 안의 케이블·설정 포함), ⌘Z/⌘⇧Z 로 되돌리기.
- 휠로 이동, ⌘ + 휠로 확대·축소, ⌥ 를 누른 채 끌어도 이동. Delete 로 선택 삭제. 작업은 브라우저에 자동 저장되고, 상단 ⤓/⤒ 로 JSON 파일로 내려받거나 불러옵니다.
- 예제는 "기본 → 기능 단위 → L2 → 서비스 → 무선" 순으로 묶여 있고, 불러오면 무엇을 해 보면 되는지 안내가 뜹니다.

## 배포
- `main` 에 push 하면 GitHub Actions 가 `tsc` + vitest 게이트를 지난 뒤 이미지를 `ghcr.io/youseonghyeon/net-sim:<sha>` 로 올리고 `deploy/values.yaml` 의 태그를 봇 커밋으로 갱신합니다. ArgoCD(`argocd/application.yaml`, 한 번만 `kubectl apply`)가 `deploy/` Helm 차트를 `app` 네임스페이스에 자동 sync 합니다.
- 이미지는 `vite build` 결과를 nginx(비특권, 8080)로 서빙하는 정적 SPA 입니다. 인그레스는 Tailscale + Funnel → `https://net-sim.<tailnet>.ts.net`.
- 로컬에서 차트만 확인: `helm lint deploy && helm template net-sim deploy`.

## 단계
1. ✅ 디자인 시스템 + 캔버스 에디터
2. ✅ DHCP 시뮬레이션 (라우터 토글, 자동/수동 IP), ping, 패킷 애니메이션, 이벤트 로그
3. ✅ 인터넷 노드, 라우터 WAN(ISP DHCP), NAT
4. ✅ TCP: 3-way handshake, 시퀀스/ACK, 데이터 3세그먼트, FIN 종료, RST 거부, 손실 시 재전송, NAT 포트 변환
5. ✅ 기능 단위 장치: 게이트웨이(다중 서브넷 라우팅 + 스태틱 라우팅 + DHCP 릴레이), NAT 박스, 호스트 DHCP 서버 서비스(서브넷별 풀)
6. ✅ DNS(호스트 리졸버·캐시, DNS 서버 서비스, 라우터 포워더, 공인 DNS, DHCP 옵션), 포트 포워딩(라우터·NAT 박스, 외부 접속 실험), 허브
7. ✅ 방화벽 규칙(기본 정책, Stateful 검사)
8. ✅ 무선 AP·스마트폰·공유기 Wi-Fi (SSID + 전파 범위)
9. ✅ VLAN: 스위치 포트별 액세스/트렁크, 게이트웨이 서브 인터페이스(router-on-a-stick)
10. 로드맵의 장치·서비스 항목은 모두 완료. 실제 네트워크 연결은 하지 않기로 함 (`docs/ROADMAP.md`)
